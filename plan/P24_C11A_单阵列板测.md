## 1. 目标与非目标

在实体VCU118上由Rocket真实执行同一个已验证Tile Program/artifact，取得C字节、AM/事件trace和计数器，对照独立oracle与validator。证明单阵列端到端路径，不拿JTAG连通、UART打印或仿真结果冒充运行。

本任务完成F01证据消费以及单阵列适用的F02/F03/F04/F06/F07/F08；**矩形与多阵列覆盖留到P28，F05此时未完成**。不因此减少全V1最终范围。可在单阵列8-slot配置证明单engine能持有超过两个handle，但不能用它替代多阵列的两链并行。

## 2. 输入、硬件访问与安全

1. 读取P23 manifest，核对器件XCVU9P、目标频率、bitstream/firmware/ABI/配置hash；使用其UART、SD/JTAG和DDR装载路径。
2. 从工具可达信息检查VCU118电源、JTAG枚举、UART设备和实际访问权限；不能要求用户重复提供可检测路径。
3. 板卡、Vivado硬件服务器/license、USB-JTAG驱动或udev权限缺失时记录具体缺口。宿主安装与udev更改由用户自己完成；不得sudo修复。
4. 映射最小所需设备，不使用privileged或宿主Docker socket；烧写命令明确目标设备，不能烧写枚举到的第一块未知板卡。
5. P03独立golden与P09/P22 artifact是测试输入，C结果只从板载DDR/导出通路读取。不得由脚本把golden预写输出地址。

没有实体板卡时可完成board-tests runner及其离线解析回归，但本任务状态仍为阻塞，不能以mock transport通过B层。

## 4. 实施步骤

1. **定义数据包和导出。** 一个run包包含artifact、A/B/可选bias参数、独立golden、固件、完整配置与hash。UART帧包括版本、run ID、长度、校验、payload；重组完整C与trace。缺帧/CRC错/trace overflow必须失败，不能只比收到的子集。
2. **准备输出哨兵。** 用非golden固定pattern填充C与保护区，保存初值；载入A/B，执行DMA→L1 producer完成后再启动BOA。对越界写检查guard区。
3. **真实启动。** 烧写P23 bitstream、加载firmware/run包，核对板上回传manifest能力。验证Rocket指令计数/PC或可用执行trace和AM_REQ/BOA_SUBMIT记录，排除host代执行。
4. **基础数值。** 非对称A/B、单/多step、INIT覆盖垃圾、K尾块、非整M/N、四转置、f32/BF16/INT8、bias/scale/activation开关；按P03特殊值策略逐bit比较。INT8必须比较完整字节而非仅范围合法。
5. **WAIT_AM和Q09。** 构造实际满槽或同logical_am尚未释放的条件，保存一次request→park→wake→PC越过ALLOC轨迹；用FINAL(slot0)→ALLOC(slot0)→await旧事件证明事件与AM独立。测试运行中不插入reap来“帮忙”。
6. **背压。** 通过P23寄存器阻止L1 output服务，在compute/commit之后观测lease/quota保留且无成功终态；外部撤除背压后暂停原context的调度，确认硬件仍自主output/free/event，再允许固件取事件。
7. **故障/复位。** 在input read、array、RMW、drain和parked状态分别注入受控fault/reset，验证取消请求永不wake、旧访问结清、代数更新。之后不清整片AM，换不同输入重跑证明无污染。
8. **contexts与长期压力。** 1/2/4/8contexts、bundle1/2、短长链和受限credit；用固定seed可重现的有限随机程序持续施压，必须保证producer最终完成且背压最终撤销。watchdog只报告失败，不通过timeout强清quota。
9. **审计并回存。** 导出完整actual/golden、trace、PMU/mcycle、board/device ID、运行环境和命令。比较非时序计数，检查所有owner资源归零。保留首次失败run和波形/ILA辅助材料，不重试直到偶然成功。

## 5. 必跑场景

| ID        | 构造                                | B层必须观察                                                              |
| --------- | ----------------------------------- | ------------------------------------------------------------------------ |
| F02-A     | 方形四转置、尾块、特殊值，三种输出  | 完整C bytes匹配P03 oracle，guard区不变；矩形列为待P28                    |
| F03-A     | 全部成功完成的有限程序              | request=grant=ALLOC，final=slot_free，park=wake，live/pending/reserved=0 |
| F04 / Q07 | output背压后撤销，旧context不再运行 | 受阻时lease保留，恢复后硬件自主free/event                                |
| F06 / Q01 | 真正parked请求                      | 每个ALLOC恰好一个AM_REQ，唤醒交付lease而不是重试许可                     |
| Q04 / Q09 | 同logical slot复用且旧事件未reap    | slot_free才新授予，随后仍可await旧事件，不死锁                           |
| F07 / Q05 | parked/fault/reset及下一次运行      | 被取消请求不wake，generation安全更新，新C正确                            |
| F08-A     | 1/2/4/8contexts固定seed压力         | 无丢请求/无挂死/无泄漏，逐链偏序成立，trace无overflow                    |
| INPUT-A   | 多读者/延迟最后读/立即覆盖          | input_release后覆写不改变正确C，不能提前释放                             |
| CONV-A    | P08小型im2col Conv                  | 软件展开+BF16 Matmul与独立Conv参考一致，无硬件LoopConv                   |

故障场景不使用`request=grant`或`final=slot_free`的成功等式，另列rejected/cancelled/fault-released账本，检查闭合运行park=wake+cancel。terminal success必须晚于安全释放；发生部分输出故障时不能仍报成功。

## 6. 命令与输出合同

P24实现下面的board target扩展：`--program-manifest`指向P23构建产物，`--serial`明确UART设备，`--jtag-device`明确容器需映射的设备。设备值由实际探测/运行环境提供；脚本不自动扩大权限。`--seed`固定可复现压力输入。

```bash
hardware/scripts/check fpga-board vcu118 \
  --config hardware/configs/vcu118_single_array.yaml \
  --program-manifest /tmp/boa-p23/single/manifest.json \
  --serial "${BOA_UART_DEVICE:?set detected UART device}" \
  --jtag-device "${BOA_JTAG_DEVICE:?set detected JTAG device}" \
  --seed 2401 --out /tmp/boa-p24/single
hardware/scripts/check fpga-board vcu118 \
  --config hardware/configs/vcu118_single_array_8ctx.yaml \
  --program-manifest /tmp/boa-p23/ctx8/manifest.json \
  --serial "${BOA_UART_DEVICE:?}" --jtag-device "${BOA_JTAG_DEVICE:?}" \
  --seed 2408 --out /tmp/boa-p24/ctx8
```

预期输出包括manifest、逐case summary、actual/golden二进制、完整UART原始帧和解析trace、PMU、各成功/失败资源账本、mcycle、器件与固件启动证据。board target必须真实烧写/运行/读回，未接板非零失败。

压力默认下界：每配置至少1000条完成链，至少覆盖所有指定fault/背压插入点；同时记录运行时长和trace容量。若trace不能容纳全程，按独立run分段完整导出并检查每段，不以丢弃trace覆盖F08。
