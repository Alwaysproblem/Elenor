## 1. 目标与边界

完成全部既定能力的可复现交付：软件显式AM、数值模型、有限周期资源、Scala/Gemmini RTL、validator联仿、真实Rocket UCE、矩形/四转置/后处理/Conv、多阵列和VCU118真实板测。交付的是能重新运行的实现与证据包，不是一篇宣布完成的总结。

本任务发现任何未完成的必达项，应修复其唯一实现并重跑受影响下游gate，不以“后续支持”删范围。源CFG、跨Tile AM、多Tile FPGA等原有非目标继续不做，不因收尾而扩大功能。

## 4. 具体步骤

1. **覆盖审计。** 以30号矩阵每行生成coverage记录，字段至少ID、required_layer、actual_layer、task、case、manifest、status。T/Q/F/R以及额外数值/环境要求必须全覆盖，禁止一个泛化“end-to-end通过”代替各case。
2. **软件全gate。** 在锁定软件环境执行pre-commit和全pytest，运行boa-am-matmul真实bytes smoke、split-K调度/资源smoke及compiled-only replay。旧artifact必须明确拒绝；estimate不能被numeric backend静默执行。
3. **RTL代表集重跑。** 从干净目录编译单阵列、两个矩形、2/4engine与Rocket系统；真实跑numeric、protocol、finite-credit、cosim、Q09/故障/背压。局部已通过但最终集成改变路径的case必须重跑。
4. **复现包建立。** 每包存完整配置、源码/dirty diff、依赖pins/镜像、输入seed/hash、artifact、golden、firmware、RTL/library/bitstream hash、命令与输出。缺外部依赖时明确准备步骤，不能假设他人有原作者缓存。
5. **冷构建和离线。** 显式联网准备锁定依赖后，从干净checkout/输出目录构建；第二次使用同一锁定镜像和已完整下载依赖且禁网运行。依赖下载cache可以预装，但上次编译产物不能成为正确性前提。
6. **确定性。** 相同配置与输入的功能/周期/RTL仿真输出bits和周期可重复；Rocket模式保留其真实开销。板测与validator周期不同是允许的，板测重复也不强求硬件运行周期逐次相等，但bytes/所有权/事件偏序和非时序计数必须一致。
7. **板级抽查复跑。** 使用P28最终manifest在真实板卡重跑至少主4engine数值、Q09和背压/故障恢复，确认release打包/重构没有绕过真实执行；其余F02矩形等消费同源码hash的P28完整证据。
8. **公平比较。** 消费并复跑P26的比较：相同MAC数、AM总容量、端口/带宽、时钟和精度下，输出驻留不均时共享与私有分区容量利用、单/多context、低冲突/hotspot、FINAL drain对短任务的影响。私有分区仅是明确标注的实验参考模型，不提供生产私有AM后门。必须有真实请求轨迹和可重复数据；缺对照证据不能关闭此项，更不能写性能优势结论。报告容量利用、compute/输入/bound-engine/AM/output阻塞与租约驻留。
9. **清理与文档。** 仅删除本次实现的临时scaffold/throwaway脚本和obsolete aliases，保留必要回归、golden与合法许可证。同步新ABI/config/命令示例，删除已废弃轮询TRY/BUSY描述，但保留明确标记的历史记录。
10. **最终交接。** 输出逐层覆盖、可重复命令、残余限制、工具/板卡要求和已冻结设计决定。计划索引只有所有门已满足才标通过；不把文档已写作为硬件实现完成。

## 5. 验收命令

现有Python入口在仓库根执行；硬件release target与参数由本任务实现并记录到help。软件或硬件环境若前序已转成容器入口，使用对应锁定封装并保留等价命令，不绕过环境锁。

```bash
conda run -n elenor-validator pre-commit run -a
conda run -n elenor-validator python -m pytest pipeline_validator/tests/ -q -n 4
bash examples/run.sh boa-am-matmul --json --report /tmp/boa-p29/boa-report.json
bash examples/run.sh matmul-splitk-pipeline --json --report /tmp/boa-p29/splitk-report.json
bash examples/run.sh matmul-splitk-multicontext-pipeline --json \
  --report /tmp/boa-p29/multicontext-report.json
hardware/scripts/check release --evidence-root plan/evidence --out /tmp/boa-p29/release
hardware/scripts/reproduce /tmp/boa-p29/release/manifest.json \
  --out /tmp/boa-p29/offline --offline
```

`release` 须实际运行它声明的smoke，验证输出bytes、资源不变量、trace与coverage；不能反复运行直到偶然通过，首次失败必须保留。它可引用P28板测清单，但缺设备时不能把需要重跑的B层记PASS。

输出目录由runner创建；CLI smoke只证明其实际检查项。对boa-am数值，必须额外消费P09独立golden比较器的结果；CLI exit0/`completed=true`本身不代表bits正确。split-K的非数值EVU combine不变成golden来源。
