# BOA / Gemmini 逐任务实施计划

依据：[总体设计 v0.5](../design/proposal/BOA_Gemmini_Integration_Design.md)。目标：让其他模型每次读取一个任务文件，完成一个可验收的实施单元，再交接下一项。

**计划覆盖不代表实现完成；实际状态以本表与 evidence 为准。** 共 29 个任务；已有 S0 软件 gate 不重造，但必须在新合同下重验。默认按下表顺序执行。先读 [00 执行总则与共享合同](00_执行总则与共享合同.md)，验收追踪见 [30 验收矩阵](30_验收矩阵与需求追踪.md)。

## 2. 分阶段出口

- **P01–P09：软件基线和对齐。** 保留已完成源 IR，补齐 Tile 拓扑、engine、数值、terminal、INT8/后处理与软件 Conv。P09 给出新的软件基线，旧周期不能沿用。
- **P10–P18：单阵列 RTL。** 显式包括 allocator、事件、有限 result/RMW 服务；这些是原 §7.2 简图未画全、但正文 C4/C5 要求的真实前置。
- **P19–P22：联仿和真实 UCE。** 先证明 Python UCE→RTL，再真实 Rocket 固件；两个控制权威不得同时执行同一 Task。
- **P23–P24：单阵列 VCU118。** 锁定工具、时序通过、实际板上 bytes/协议检查；单阵列通过不冒充矩形/多阵列通过。
- **P25–P28：矩形、多阵列与第二轮上板。** 8×16、16×8、2/4 engines、四种 transpose、每 Tile 共享八槽都是必达项。
- **P29：完整 V1。** 按 T/Q/F/R 矩阵逐项核验证据和离线复现；明确区分功能、周期、RTL、板上与 PPA。

最小依赖允许 P04/P07 等软件项不等 P02 的硬件环境；默认顺序仍优先减少交接分叉。P25 可在 P24 之外先做 RTL；P26 默认保留“单阵列上板后再扩多阵列”的用户验证顺序。不能因为板卡阻塞把 P24/P28 从最终范围删除。

## 3. 给下一个模型的最小输入

```text
请只实施 plan/P01_C0S_S0_软件基线.md。
先读 plan/00_执行总则与共享合同.md，按任务文件执行。
不要重新规划整个项目；不要开始下一任务。
完成实际 smoke/验收、受影响文档更新及 plan/evidence/P01.md 后，
把 plan/README.md 中 P01 的状态更新为通过；有真实外部阻塞则写明证据。
```

以后替换任务 ID/文件名即可。每个任务文件都包含目标、前置输入、读码入口、修改边界、接口、步骤、正反例、命令、交付与阻塞条件；不依赖执行模型记得前一轮聊天。

## 4. 防止范围遗漏

- S0 已完成与待做项分开；P09 不把 IR13 的旧延期项自动变为新源级 CFG。
- P03 冻结 NaN/INT8/后处理舍入，P10 冻结 wire ABI，P11 冻结 dataflow，P16/P23 冻结物理服务和 FPGA 映射；未决项都有 owner，不留给下一个模型猜。
- Q09 永久 runtime 回归随 P04 补齐；硬件/真实 UCE/板测仍需各自复现。
- T16 的原子等待竞态在 P15/P22 验，不新增 `tile.await_any` 等源操作。
- Q08 用软件双 Tile 与 RTL 双实例证明；不扩大到多 Tile FPGA。
- P28 的 F02 必须包含矩形上板配置；不能只在 P25 RTL 通过就声称板上矩形通过。
- 默认 HardFloat，不要求另做定制 BF16 fused MAC；若为 PPA 换实现，重新做 P03/P11/P12/P20 对拍。
- 无 Vivado/license/VCU118/JTAG 时明确阻塞相关任务，仿真不能代替 F 项。
