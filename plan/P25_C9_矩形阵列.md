# P25 · C9 矩形阵列（8×16 / 16×8）

状态：未开始
对应原方案：§7.2 C9、§3.1（固定 tile、阵列数据流和转置）、§3.2（tile_k 数值参数）
验证层级：C（周期后端若已参数化 shape）与 R（联仿 bytes 对拍）；板级矩形归 P28 的 F02，不在本任务宣称。

## 1 目标与不做

目标：

1. 交付 8×16 与 16×8 两种矩形阵列配置，作为可执行 `hardware/configs/` 实例（`rect_8x16.yaml`、`rect_16x8.yaml`，字段拼写沿 P05 交接的 `array_rows/array_cols`/`tile_m/tile_n/tile_k`）。
2. 四种转置（不转置 / A 转置 / B 转置 / 双转置）在两种 shape 下全通过；馈数/排空的 row/column skew、有效 mask、tag/last、drain 证明按矩形独立推导，不沿用方形 block_size 假设。
3. 完整 bytes 对独立 oracle（P03），覆盖不同 M/N/K、尾块、首/末有效输出、气泡输入。
4. 合同不变：形状改变不改变 quota、affinity、step_committed、FINAL 自动释放合同（C9 guide）。

不做：tile_k 暗改（默认保持 8，进 fingerprint；改 16 属数值 profile 变更，须走 P03/P06 重冻结，本任务不做）；方形数据流重写（P11/P12 已冻结 dataflow）；多阵列共享 AM（P26）；板级综合与上板（P27/P28）；新源 IR 形状语法。

## 2 前置与输入

- P12：方形 mesh 与不可暂停输出合同（含 16×16 与另一方形配置的 adapter 经验）。
- P18：单阵列 top 集成（mesh 尺寸参数化入口、ResultCapture/AmRouter 与 E 的关系）。
- P20：`validator-cosim` 通过——矩形 bytes/事件验收在联仿层执行；周期后端对拍基准同法。
- 输入：P03 oracle 向量（含非对称形状用例）、typed artifact 生成链、`examples/run.sh` 场景管理约定。

## 3 当前证据、必读与修改边界

- 现有软件/RTL 均按 16×16 方形推演（§1.3/§7.2 C2）；无任何 8×16 或 16×8 实现，配置实例为拟新增。
- shape 参数落点：P05/P06 是新硬件配置与 fingerprint 的唯一软件落点（总则 §4.1）；本任务只提供配置实例与 mesh/feed/drain 的参数化实现，不另建配置解析器。
- 修改边界：`hardware/gemmini/`（mesh 生成与 feed/drain 参数化）、`hardware/configs/rect_*.yaml`（拟新增）、validator 侧仅在配置驱动的既有参数路径上核对（不改 P04–P07 合同代码）。
- 必读：§3.1 dataflow 与转置定义、P13 四转置与 L1 请求交接、P12 输出合同、P20 backend 用法。

## 4 接口与不变量

- array_rows/cols为8/16和16/8；tile_k保持8，tile_m/n按所选dataflow与adapter合法分块确定（如8/16或16/8），不能把方形16/16强当矩形限制。若逻辑16×16跨物理块则显式验证拼接；全部参数进target fingerprint。
- skew/tag/last/drain：row/column skew 由 mesh 形状与 dataflow 独立推导；每拍有效 lane mask 由 tile_m/tile_n 与矩形形状共同决定；tag/last 标记首/末有效输出；drain 排空全部有效行且不早于 last。
- 数值不变量：BF16 输入、逐 MAC `fma_f32_rne`、INIT 首块覆盖、尾块无效 lane 旁路不补零 MAC；`tile_k` 进 target fingerprint。
- 资源不变量：quota=2、bundle≤2、affinity 至 slot_free、O+R≤Q、不可暂停块输出量合同均按形状重新核算，不允许"矩形借方形配额"。

## 5 实施步骤

1. skew/mask 推导：对 8×16 与 16×8 分别推导馈数排程（首拍有效列/行、气泡拍数）与排空排程（last 到 drain 拍数），写成可执行的期望表（测试输入，不是断言周期常数）。
2. mesh/feed 参数化：P18 top 的 mesh 生成接受 rows/cols；operand feeder 按 §4 掩码发数；四种转置路径逐 shape 核对地址映射（复用 P13 转置单元，不新写第二种转置实现）。
3. 周期后端核对：若周期模型已按 config 参数化 shape，先在 C 层跑通再进联仿；若未参数化，按 P05 配置映射补齐，不旁路模型。
4. 联仿验收：`rect_8x16/16x8` 配置 + typed matmul artifact，经 P20 backend 取 bytes/事件；oracle 对拍。
5. 尾块与气泡：构造 M/N 不整除、K 尾块、输入气泡的用例；验证首/末有效输出 tag、drain 完整性。
6. 注册 `rectangular` target cases；`examples/run.sh` 增加/更新对应场景（遵守 fidelity-of 约定，不硬编码 fidelity override）。
7. 文档同步：原方案 §7.2 C9 输出条目链接本任务 evidence；方形/矩形覆盖分开记录。

## 6 验收表

| Case ID                     | 构造                                          | 必须观测                                         | 失败特征                             |
| --------------------------- | --------------------------------------------- | ------------------------------------------------ | ------------------------------------ |
| rect-8x16-bytes             | 8×16 配置 typed matmul（M/N 适配矩形）        | C bytes 与 oracle 逐 bit 一致；事件偏序合法      | 用周期后端结果当 oracle              |
| rect-16x8-bytes             | 16×8 配置同上                                 | 同上                                             | 同上                                 |
| rect-8x16-4t / rect-16x8-4t | 两 shape × 四转置                             | 四种转置各自 bytes 正确，地址映射互不混淆        | 复用同一份输入不换转置               |
| rect-tail                   | M 或 N 非整除、K 尾块                         | 无效 lane 旁路（无补零 MAC），尾块 bytes 正确    | NaN 注入被补零 MAC 吞掉              |
| rect-first-last             | 首末有效输出观测                              | tag/last 正确，drain 覆盖全部有效行且不早于 last | drain 早退丢行                       |
| rect-bubble                 | 馈数气泡注入                                  | 无数据错位，compute_done 不早于全部有效 MAC      | 气泡拍被当作有效数据                 |
| rect-contract               | 同源程序/输入分别按方形和矩形编译匹配artifact | quota/affinity/free语义与非时序计数合法          | 跨target直接复用旧artifact或合同漂移 |
| rect-fp                     | 改 tile_k 或形状后重编译                      | fingerprint 变化被拒绝加载旧 artifact            | 旧 artifact 静默可跑                 |
