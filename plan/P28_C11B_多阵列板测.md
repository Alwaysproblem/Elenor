# P28 · C11-B：VCU118 多阵列最终板级验收

- 状态：未开始。
- 前置：**P24、P27** 通过；使用P27完整实现的2/4engine和两个矩形bitstream。
- 依据：原方案 §6.2、§7.4.8、§8.1–8.2；重点F01–F08、Q01/Q04/Q05/Q07/Q09。
- 公共规则：[总则](00_执行总则与共享合同.md)；覆盖矩阵：[30](30_验收矩阵与需求追踪.md)。

## 1. 目标与范围

完成1 Tile×4阵列的最终板上数值、所有权、进展和异常恢复验收；同时用2engine与矩形配置补齐不可由4×16×16单一配置证明的能力。继续复用P24的真实Rocket固件/板测入口，不从host直接驱动阵列绕过UCE。

FPGA仍不支持多Tile；Q08由P04/P15/P26双实例软件/RTL证据负责。四engine利用率与ASIC频率/PPA是不同概念；板测只报告实际mcycle、PMU与吞吐，不宣称ASIC性能。

## 2. 输入与修改范围

- P27四配置manifest、bitstream和post-route报告；P24板卡/USB/UART授权及工具。
- P26多阵列合法调度用例、P25矩形golden/trace、P03数值vectors、P08 Conv与后处理、P22真实固件。
- 扩展 `hardware/fpga/board-tests/` 的多阵列case与结果审计；复用 `hardware/scripts/check fpga-board`。
- 必要输入由 `examples/generators/` 的权威生成器或P03/P26测试生成器产生；不要手改生成的IR/compiled artifact。输入/程序/config/golden hash同时入manifest。
- 不在板测里修改实际bound_engine、group、quota或credit强造状态；配置和工作负载须经同一loader/verifier。

## 3. 实施步骤

1. **逐bitstream核验。** 烧写前验证器件、WNS、RTL/firmware/config兼容与hash；启动后读能力回执，与host manifest逐字段核对。板级程序不能无视arrays/profile不匹配。
2. **方形主基线。** 在4engine16×16上运行单/多K-step、非对称四转置、M/N/K尾块、垃圾INIT、special values以及f32/BF16/INT8完整后处理；C逐bit比较，检查无效lane不越界。
3. **四路并行。** 两contexts各两条ready链，least-live自然绑定0/1/2/3；通过不同engine的issue/compute区间重叠证明不是全局串行。单context四独立输出必须分两批，不得超过两live leases/两同时工作的engine。
4. **固定affinity。** 让某链两step之间原engine繁忙而其他engine空闲；第二step等待原engine，不迁移。trace必须有明确bound-engine等待原因。等待输入时同engine其他ready链可运行，避免整链独占。
5. **超过两handle。** 在2engine/8slot配置用四contexts各两链，合法达到每engine4live handles，再按step公平交替。观察metadata完整、无每engine2槽隐限。不得要求4engine均衡策略下自然出现第3handle。
6. **跨engine同group。** 利用slot的group/index顺序与engine独立least-live选择，构造两个engine访问同group不同region；验证路由身份、group仲裁和并行其他group。hotspot时阻塞符合port/adder服务，不丢partial。
7. **credit压力。** 同时burst，多在途微块，检查每层O/R与launch限制；针对Q=8/O=6/R=2边界禁止新发射，到达仅R→O。板级读数和trace必须能还原不变量，不靠测不到溢出来宣布通过。
8. **矩形逐个运行。** 切到8×16和16×8的4engine bitstream；每个四转置、非整M/N/K、首/末有效输出、input bubbles、FINAL drain，完整C逐bit比较。只在RTL通过不算F02 B层。
9. **背压与自主释放。** 对多group持续ADD与FINAL drain争用读端口；注入L1 output背压再撤销，停止原context运行仍须自主完成；drain公平，FINAL到free的延迟可解释。
10. **挂起/事件/故障。** 重跑Q01/Q04/Q05/Q07/Q09、满槽fresh FIFO、bundle保护续链、事件早到、slot换代旧事件、各阶段fault/reset。故障后以新输入运行，不物理清AM。
11. **长期压力。** 固定多个seed，覆盖1/2/4/8contexts、bundle1/2、短长链、变化stride/epilogue参数、input与output暂停，保障外部输入/下游最终恢复。每配置至少1000条完成链，主4engine配置至少10000条；记录实际时长与case分布。trace容量不足则分run完整导出，溢出run不用于通过顺序验收。
12. **比较与汇总。** 对同artifact/input运行validator参考；数值与非时序计数比较，park/wake和周期只报告不要求相等。逐链偏序、所有owner/slot/credit/输入引用清零，成功/错误终态分开统计。

## 4. 必跑板级矩阵

| 验收               | 配置/场景                                    | 必须观察                                                                     |
| ------------------ | -------------------------------------------- | ---------------------------------------------------------------------------- |
| F01                | 四个P27构建                                  | 锁定来源、真实bitstream、WNS≥0，板上回执与manifest一致                       |
| F02                | 方形/8×16/16×8、四transpose、tail/special    | f32/BF16逐bit一致；额外必达INT8/bias/scale/activation/Conv字节一致           |
| F03                | 完全成功运行                                 | request=grant=ALLOC，final=slot_free；闭合park=wake，live/pending/reserved=0 |
| F04 / Q07          | 多array持续ADD且L1背压                       | 不提前free，撤销背压后无需原context动作自主完成                              |
| F05-a / T04/T20    | 4engine，两contexts各两链                    | 每链affinity不变，真实四路计算重叠；单context≤2                              |
| F05-b / T06        | 2engine，8live handles                       | 每engine可有4handles，按step公平推进，不是整链独占                           |
| F06 / Q01/Q04/Q09  | 一次AM_REQ、同logical slot复用、旧事件未reap | grant一次、wake一次、PC只在wake后恢复、旧事件仍可读                          |
| F07 / Q05/T17/T19  | 各阶段fault/reset与再次运行                  | 取消永不wake、安全换代/回收、失败不报成功、新输入C正确                       |
| F08                | 长期合法随机程序+背压                        | 无挂死/泄漏/trace overflow，保留mcycle与分类stall                            |
| PORT / T10–T12/T22 | burst、hotspot、RMW同址、drain争用           | O+R守恒、地址互锁、group并行、公平drain有证据                                |
| CONFIG / T18       | contexts交错stride/transpose/scale           | ACCEPTED后配置不串扰、不同context结果均正确                                  |

取消/错误run的F03改用单独账本：有效请求=授予+未授予取消（闭合且无pending时，永久ERROR另计），park=wake+挂起cancel；lease最终安全回收数包括success和fault，不能硬套final=slot_free。

## 5. 命令合同

这些入口由P24已实现，P28增加case清单与统计审计。设备环境变量取真实探测结果；每次config与program-manifest必须配对。

```bash
hardware/scripts/check fpga-board vcu118 \
  --config hardware/configs/vcu118_multi_array_4.yaml \
  --program-manifest /tmp/boa-p27/e4/manifest.json \
  --serial "${BOA_UART_DEVICE:?}" --jtag-device "${BOA_JTAG_DEVICE:?}" \
  --seed 2804 --out /tmp/boa-p28/e4
hardware/scripts/check fpga-board vcu118 \
  --config hardware/configs/vcu118_multi_array_2.yaml \
  --program-manifest /tmp/boa-p27/e2/manifest.json \
  --serial "${BOA_UART_DEVICE:?}" --jtag-device "${BOA_JTAG_DEVICE:?}" \
  --seed 2802 --out /tmp/boa-p28/e2
hardware/scripts/check fpga-board vcu118 \
  --config hardware/configs/vcu118_rect_8x16_4.yaml \
  --program-manifest /tmp/boa-p27/r8c16/manifest.json \
  --serial "${BOA_UART_DEVICE:?}" --jtag-device "${BOA_JTAG_DEVICE:?}" \
  --seed 2816 --out /tmp/boa-p28/r8c16
hardware/scripts/check fpga-board vcu118 \
  --config hardware/configs/vcu118_rect_16x8_4.yaml \
  --program-manifest /tmp/boa-p27/r16c8/manifest.json \
  --serial "${BOA_UART_DEVICE:?}" --jtag-device "${BOA_JTAG_DEVICE:?}" \
  --seed 2818 --out /tmp/boa-p28/r16c8
```

同一配置长期压力还须换seed运行，失败保存第一次输出。所有命令由脚本保存原样到manifest，不能把示例目录存在当任务已跑。

## 6. 产物、交接与完成条件

每run输出完整输入包、artifact、actual/golden、原始UART、解析trace、PMU、mcycle、资源与请求账本、逐case结果及bitstream/firmware/config/tool hashes。P28 evidence按F01–F08及Q01/Q04/Q05/Q07/Q09逐项链接B层证据；矩形和2engine结果不能只写“参照4engine”。

P28通过后向P29交付完整B层索引和可复现输入/命令。缺板卡、任一必达配置失败、输入/trace不完整、数值不一致、用poll触发release、资源残留都阻塞；不能改成“其余后续支持”结束。
