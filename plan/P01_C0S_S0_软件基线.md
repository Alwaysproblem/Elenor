# P01 · C0-S / S0 软件基线与差距清单

状态：未开始
前置：无（P02 的硬件环境不阻塞本任务）
对应原方案：C0-S、S0（[设计 v0.5](../design/proposal/BOA_Gemmini_Integration_Design.md) §1.3、§7.2）；既有 S0 证据见[软件实施报告](../design/proposal/BOA_Software_Managed_AM_IR_Implementation_Report.md)。

## 1. 目标与不做

目标：在不动任何实现代码的前提下，把当前 Python/xDSL validator 环境固化为可复现基线，重跑现有软件 gate 取得**当日真实数字**（不沿用实施报告 §4 与设计 §8.3 的历史数字），并按设计 §1.3 逐条核对源码事实、产出映射到 P02–P09 的差距清单。

不做：不改 Python/配置/IR/fixture；不做硬件工具链（P02）；不实现任何 SW-A/C6-S 项；不生成 `plan/evidence/` 以外的证据文件；不把本任务的新数字当作新合同验收（新合同基线在 P09 建立）。

## 3. 当前证据与必读/修改文件

必读（只读核对，注意行号可能已漂移，必须以符号定位）：

- `pipeline_validator/tile_group.py`：构造函数创建 `SharedAmManager(..., tile_id=0)` 并注入所有 `ComputeTile`（SW-A1 差距，→P04）。

- `pipeline_validator/execution_verifier.py`：`target_fingerprint` 与 `_HW_TARGET_FIELDS`（P05/P06 新键落点）。
- 无 `hardware/`、`.devcontainer/` 目录（P02 全部拟新增）。

新建 `pipeline_validator/environment.lock.explicit.txt`、`environment.lock.yml`、`environment.lock.pip.txt`（均在pipeline_validator下）与P01 evidence；允许更新索引状态，不改功能实现。pre-commit可能改格式：记录输出，不擅自回滚用户改动。

## 4. 输入输出、接口与不变量

- 输入：当前 worktree（以 `git rev-parse HEAD` + dirty diff hash 记录）、conda env、examples fixtures。
- 输出：conda explicit清单、environment.yml导出、pip来源/版本/wheel hash补充清单与差距evidence。
- `conda list --explicit`不覆盖全部pip包，也不能仅靠URL清单完成离线安装。分别锁conda与pip依赖，记录源/构建hash；P02在显式下载阶段备齐离线包后实际重建验证，不能在P01仅导出就宣称完整离线复现。

## 5. 实施步骤

1. 记录source身份：HEAD、staged/unstaged diff及本次相关untracked源文件的内容hash；单独 `git diff` 不包含全部工作树变化，不能作为完整dirty身份。日志置evidence，不改历史或分支。
2. 导出conda explicit（使用支持的hash选项）与完整env；核对python/xdsl及pip段，补pip exact版本、wheel/源码来源和hash。包获取仅在现有环境允许的显式下载/容器阶段，不在宿主全局安装；不可重建来源列为明确缺口，交P02验证。
3. 运行现有软件 gate（真实执行，记录 exit status 与完整计数）：
   `conda run -n elenor-validator pre-commit run -a`
   `conda run -n elenor-validator python -m pytest pipeline_validator/tests/ -q -n 4`
4. 运行 typed smoke 与回归样例（记录 cycles/makespan、report checks、AM snapshot 计数）：`bash examples/run.sh boa-am-matmul --json --report /tmp/p01/boa-am.report.json`；再抽 `bash examples/run.sh matmul-splitk-pipeline`、`bash examples/run.sh gather-matmul-4tiles-2contexts` 各一次。核对 report 的 `task_completed`/`credit_invariant`/`arena_zero_leak`/`am_slot_zero_leak` 通过。
5. 逐符号核对并记录“差距→任务owner→源码证据”，包括SW-A1–A4、INT8/epilogue/数值Conv与环境来源缺口；发现原方案现状过期则更新本计划事实记录，不需依赖原撰写会话或Main在线。
6. 版本事实段：记录 schema v4/v4、`--compiled-file`、`target_fingerprint` 字段清单、无 `hardware/` 目录。这些是 P02/P05/P06/P08 的输入。
