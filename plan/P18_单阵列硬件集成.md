# P18 · 单阵列 BOA top（C2–C6 集成 gate）

| 项 | 值 |
| --- | --- |
| ID | P18（对应原方案 C2–C6 集成 gate） |
| 前置 | P12、P13、P14、P15、P16、P17 |
| 状态 | 未开始 |

## 1. 目标与不做

**目标**：把 P12–P17 交付的真实 RTL 模块集成为单阵列 BOA top（1 engine bring-up 形态，`arrays_per_tile=1`），接 Tile L1 SPM 与受控 harness，跑通端到端 typed Matmul 链（INIT/ADD/FINAL/one-shot），在 R 层复验 T/Q 矩阵的适用子集，并执行集成门清单。这是真实 RTL 集成，**禁止以抽象模型单测替代**。

**不做**：不实现 RoCC/Rocket（P21）与 C ABI 联仿（P19/P20；本任务只提供内部 chiseltest/Verilator harness）；不做 4-engine 满载与多阵列（P26/P27 范畴；4-engine baseline 板级配置归 P27/P28）；不做矩形（P25）；不做 FPGA 综合（P23）。

## 2. 前置与输入

- P12：方形 mesh + `min_nonstoppable_outputs`；P13：operand/四转置/L1 请求；P14：allocator/ChainTable（含 1-engine 配置）；P15：事件/取消/收尾；P16：credit/RMW/仲裁；P17：epilogue/drain。全部「通过」状态，各 evidence 为输入。
- P10 的生成 codec 是 top 内全部命令/响应消息的唯一编码来源。
- 原方案必读：§2.1（组件职责表——top 的模块清单）、§3.3–§3.6、§5.2（进展条件）、§7.2 C2–C6、§7.4.2（模块框图与 TileAmAllocator 串行化点）、§8.1 T 表、§8.1b Q 表、§8.2 不变量。
- 软件参照（对照计数来源，非替代实现）：`pipeline_validator` 对同一 artifact 的非时序计数（ALLOC/commit/final/slot_free、终态成败数）。

## 3. 必读文件与修改 ownership

- 必读：本文件、总则、全部前置 evidence（P12–P17）、P10 schema。
- 新增BoaSingleArrayTop与集成测试，权威完整配置为 `hardware/configs/single_array.yaml`，供P19–P24消费；模块测试配置保持各自范围，不复制第二份完整单阵列配置。
- 注册并实现原方案规范入口 `hardware/scripts/check single-array`，使用P02公共case机制，包含下面所有PT case。
- 允许的最小修复：集成期发现的子模块接口不匹配，回到对应 owner 文件修复并在 evidence 记录；不得在 top 内复制第二套逻辑绕过。

## 4. 集成门清单（本任务的核心交付之一）

进入 top 的每个组件必须是前序任务的**真硬件模块**；逐项核对并记录：

| 门 | 组件 | 来源 | 核对点 |
| --- | --- | --- | --- |
| G1 | Gemmini 方形 mesh/PE（FP32 贯通、状态保留） | P11/P12 | PM06 状态走查在网表中成立；无 `Float(8,8)` 回退 |
| G2 | Operand/Transpose/L1 请求 | P13 | mem_req/resp 用 P10 codec；无第二套 view 解析 |
| G3 | TileAmAllocator/ChainTable/挂起 FIFO | **C4 真硬件（P14）** | PA12 全成全败授予；串行化点单一 |
| G4 | EventTracker/terminal 环/quiesce | **C4 真硬件（P15）** | 授予路径无事件槽请求线；PE01/Q09 通过 |
| G5 | ResultCapture/AmRouter/CreditTracker/AmGroup/ReadyArbiter | **C5 真硬件（P16）** | O+R≤Q 断言在 top 打开；commit 三与项 |
| G6 | EpilogueUnit/DrainController | P17 | PB07 五时刻单调 |
| G7 | 消息编码 | P10 | 全部编解码来自生成 codec，无手写常量 |
| G8 | 抽象模型隔离 | 本任务 | 真实可综合有限存储/端口与RMW datapath，无Python替DUT更新AM；实际URAM资源映射由P23综合报告确认 |

任何一项不满足即集成门失败，不得以「功能等价」豁免。

## 5. 实施步骤

1. 实例化 top：1 engine × 1 阵列 × 4 groups×2 slots；L1 SPM 适配（P13 端口）；时钟/复位沿 §7.4.2（单时钟、reset generation+1）。
2. harness：受控激励器按 P10 codec 注入 AM_REQUEST/SUBMIT_STEP/EVT_*，响应与事件时序采样到 trace（mcycle 戳 + ctx/handle/generation/seq/engine/group 字段，字段名沿原方案 §6.2 观测分解表）。
3. 端到端链：INIT 多步 ADD、FINAL accumulate output、one-shot `output`，f32/BF16/INT8 输出与完整后处理链（bias/scale/ReLU/quant 全开）各一条；输入 bytes 由 ByteStore 等价固定文件提供，golden 由 P03/P08 oracle 生成。
4. 按下表复验单engine适用部分。T04跨engine、T05、T10四路burst、T11多engine同时服务和T20完整并发归P26；当前保留其单engine可达子集。Q08由P14/P15/P26双实例RTL证明，不要求板级多Tile。INT8/四转置/后处理在当前top真实跑完整bytes。
5. 成功闭合run比较ALLOC=grant、final=slot_free等非时序计数；故障/取消run另记ERROR、cancel、fault-release分母。park/wake随周期可不同，只验各run闭合park=wake+cancel，不能强求双方park次数相等。
6. 不变量全家桶：§8.2 逐条在 top 打开断言（quota 0..2/全局 0..8、O+R、affinity 恒定、每 handle 单 issued、slot_free 清结条件）；零维/零 K 合同按 PT09 在 top 的 loader 入口与整链各验一次。
7. 注册single-array target，输出manifest/summary/trace/必要波形，更新evidence与索引状态。

### 6.2 top 验收 case

| case | 构造 | 必须观测 | 失败特征 / 层 |
| --- | --- | --- | --- |
| PT01 | INIT+2×ADD+FINAL（accumulate output）链 | C bytes 逐 bit=P03 oracle；五时刻单调；slot_free 后 chain_done | 数值或次序错（R） |
| PT02 | one-shot `output` 链 | 单 slot 短生命周期占用；自动释放无 FREE | 释放需软件（R） |
| PT03 (T13) | 满槽+新申请挂起 | 旧链 STEP/FINAL/drain 继续推进（top 级） | 进展中断（R） |
| PT04 (Q09) | FINAL(slot0)背压→ALLOC(slot0)→await旧事件 | **旧链**slot_free后新链获授予，旧事件随后仍可await | grant等reap或等新链free的循环依赖（R） |
| PT05 (T06) | 1-engine 配置 ≥3 live handles | 单 engine 服务 >2 handles 公平交替 | 隐含 2-handle 上限（R） |
| PT06 | f32、BF16、INT8 输出各一 + 完整后处理链全开 | bytes=P03/P08 golden（含 INT8 饱和/RNE/zero_point 冻结行为） | 转换或后处理错（R） |
| PT07 (Q05) | PARKED 请求遇 fault/reset + 清理后新输入重跑 | 永不唤醒；generation 递增；失败终态已发布；无残留污染 | 死请求唤醒/伪成功（R） |
| PT08 | 计数对照 | 与 validator 非时序计数一致；park=wake+cancel | 计数不符（R，对照 F） |
| PT09 (§3.1) | compiler规范化零K/零维及非法未规范化请求 | 按P06/P08定义得到零请求空输出或合法初始化/后处理输出；只检查真实发生的事件，不伪造空mesh五时刻 | 等空last或错误bytes（R/F） |
| PT10 | 集成门 G1–G8 | 全部核对记录在 evidence；任何「模型顶替」即失败 | 门未过（F 审计） |
| PT11 (T01/Q06) | 同 owner 两条未受理 FINAL 链后第三条申请；另一 owner 正常运行 | 第三链 ERROR/fault 且零副作用；一链 FINAL 受理后同申请挂起至其 slot_free；邻居 owner 无感 | 挂起自锁链（R） |
| PT12 (T02) | 8 contexts 各 1 链填满 8 槽 | 全局 8 槽用满，无每 context/engine 隐限；逐一 FINAL 后全释放 | 假隐限拒绝（R） |
| PT13 (T03) | 混合 RESERVED/WAIT_INPUT/RUNNING/COMMITTING/FINAL_READY/DRAINING/one-shot 链清点 | 每链恰计 1 lease，仅 slot_free 减一；snapshot 计数与 trace 一致 | 漏计/双减（R） |
| PT14 (T07) | 垃圾初值 AM 上 INIT、尾块 mask、bias 向量 | INIT 覆盖不读残留；无效位置不污染；bias 仅 FINAL 一次；bytes=oracle | 读残留/重复 bias（R） |
| PT15 (T08) | 重复/跳 seq、错 owner、FINAL 后提交注入 top 命令通路 | 全部拒绝且无 AM 副作用；合法流不受影响 | 副作用先行（R） |
| PT16 (T09) | 延迟结果 FIFO/RMW/writeback 注入 | compute_done 先到，commit/output 不提前；五时刻单调 | 边界合并（R） |
| PT17 (T10) | 结果流造 O=6/R=2/Q=8 继续发射 | 拒发；到达仅 R→O；出队才释放 | 到达放行（R） |
| PT18 (T11) | 多链集中同一 group、其余 group 空闲 | 热点吞吐≤该 group bank/adder 能力；空闲 group 不被拖住；等待公平可观测 | 全局串行化掩盖热点（R） |
| PT19 (T12) | 同地址 RMW、写后读、控制位变化 | read→adder→writeback 互锁/forwarding，无旧值覆盖 | hazard 旁路（R） |
| PT20 (T14) | mailbox 满触发 FULL；ACCEPTED 后改写原 descriptor | FULL 不增游标、context 转 WAIT_ENGINE_QUEUE；行为与快照一致 | 用改后配置执行（R） |
| PT21 (T15) | 两读者同 buffer，第二读者最后读取后释放并覆写 | 读者结果均不变；释放时刻≥最后读取 | 提前释放（R） |
| PT22 (T16) | 事件早到、WAIT 边界、park 与 slot_free 同拍、cancel 与 grant 同拍 | 无丢/重复唤醒、无忙循环；粘性事件即满足 | 竞态丢唤醒（R） |
| PT23 (T17) | slot 复用后旧 generation 结果/完成/事件到达 | 不影响新 owner；旧终态在保留期内可观察 | 覆盖新链事件（R） |
| PT24 (T18) | 两 context 不同 stride/transpose（含 A/B 转置组合）交错 | 配置不串扰，各链 bytes=oracle | 参数泄漏（R） |
| PT25 (T19) | FINAL drain 中 context 返回；缺 FINAL 强制退休 | FINISHING 自主收尾；缺 FINAL 报协议错误并安全收尾 | 依赖已返回 context（R） |
| PT26 (T21) | 授予路径注入元资源缺失 | 全成或全败，无占槽缺 mailbox 半成功 | 半初始化资源（R） |
| PT27 (T22/Q07) | L1 output credit 不可得 + 持续 ADD | 停 FINAL_READY/DRAINING 持有 lease；恢复后无固件动作完成；drain 无饥饿 | 提前释放/永久饥饿（R） |
| PT28 (Q01) | 不可授予申请→slot_free | PARKED 无 slot/quota/generation 副作用；恰好一次唤醒交付已授予 lease | 丢/重复唤醒（R） |
| PT29 (Q02) | bundle=2 fresh 与 continuation 混合竞争 | fresh 整 bundle 授予+预留；FIFO 不插队；预留保护续链 | 拆散 bundle/插队（R） |
| PT30 (Q03) | continuation 等待时其他 owner 释放 | 不被其他 owner 唤醒误授；只等自身 FINAL 已受理链 | 跨 owner 等待（R） |
| PT31 (Q04) | 同 logical_am 旧链 FINAL 已受理未 slot_free 时新申请 | 挂起至旧链 slot_free，即使预留有空 | 预留覆盖同槽（R） |
| PT32 | 四转置组合（A/B 各 正常/转置）端到端 one-shot 链 | 全部 bytes=oracle；stride/mask 非对称矩阵覆盖 | 任一组合错（R） |

反例边界：以「抽象 AM 模型先跑通，RTL 下轮再说」交付即违反本任务定义；波形/trace 缺失的通过声明无效。

## 7. 可执行命令（契约；target 由本任务实现）

```bash
hardware/scripts/check single-array \
  --config hardware/configs/single_array.yaml --out artifacts/p18 --seed 1

  --config hardware/configs/single_array.yaml --out artifacts/p18-pt27 --seed 1 --case PT27

```

预期：`artifacts/p18/manifest.json` 含 PT01–PT32 断言与 §6.1 适用性映射的逐项核对结果（含 T05/T20/Q08 的归处记录）、actual/golden bytes、事件/计数 trace、关键波形路径；`summary.json` 含集成门 G1–G8 结论。全部为待实现接口，target 未注册前命令必须非零。

## 8. 产物、交接与停止条件

- 产物：BoaSingleArrayTop、集成harness、single_array.yaml、single-array target、集成门记录与evidence。
- 交接：P19 用该 top 暴露 C ABI；P20 联仿接线；P21/P22 在其上挂 Rocket/RoCC；P25/P26 消费参数化边界扩矩形/多阵列。
- 停止条件：任一集成门失败且 owner 无法在 top 集成期修复；端到端数值与 oracle 不可归因差异；计数对照不一致且原因不明。

## 9. 版本、cutover 与文档同步

- 本任务交付后，原方案 §7.2 组件 guide 的 C2–C6 行按当前实现状态更新（保留评审稿历史标签）；周期/资源数字只记实测，不改写 §7.4 推导值的标注。
- 与 validator 的计数对照使用双方当前版本 artifact（P06 cutover 后版本域），manifest 记录两侧 hash；不硬钉 v4。
- 集成门 G1–G8 成为 P19/P20/P23 复验清单的基底；后续任何组件变更必须重跑受影响门，evidence 保留门状态历史。
