# P02 · C0-H 锁定工具链与统一运行入口

状态：未开始
前置：P01 通过（需要 `pipeline_validator/environment.lock.explicit.txt` / `environment.lock.yml` 作为容器内 Python 环境来源）。
对应原方案：C0-H（[设计 v0.5](../design/proposal/BOA_Gemmini_Integration_Design.md) §1.4、§7.2 C0 行、§7.3）；总则 §4.1/§4.2/§4.3。

## 1. 目标与不做

目标：交付真实可用的硬件工具链环境与统一入口：`hardware/toolchain/toolchain.lock`、按 digest 锁定的 Dockerfile、build overlay、devcontainer、`hardware/scripts/env|check|reproduce` 三个分派器、`hardware/configs/` 配置格式与 `manifest/summary` 基础结构；用锁定 pins 真实构建 Scala/Chisel/Rocket/HardFloat/Verilator/RISC-V 工具链，并以一次干净 elaborate 证明构建可用（不是打印版本）。**SoftFloat 3e 与 berkeley-hardfloat 的锁定获取与构建由本任务拥有**（P03 只消费构建产物与 pinned 源）。实现 `--case ID` 的分派/过滤公共基础，各后续任务注册自己的 target/case。

不做：不实现 Gemmini BOA 适配器/RTL（P11+）；不构建 VCU118 bitstream；不安装 Vivado（用户只读挂载，本任务只做探测与能力记录）；不改动 pipeline_validator 实现；不支持未注册 target 的任何“成功”路径。

## 2. 前置与输入

- P01 evidence、conda两份导出及environment.lock.pip.txt；在本任务实际备齐包并重建验证，而非假设导出即锁全。
- 设计 §1.4 候选 pins（起点，必须构建后才能声称已验证）：Chipyard `e02074414158c85059c1dcb231ff2f8941254b9a`、Gemmini submodule pin `25809f78323a729ef76fb68f3cedd8a24da2942b`、Rocket `c7aabd2823d3d001a7a9e8a982bb65d6cb7c9bdf`、Scala 2.13.12 / Chisel 6.5.0；Gemmini 独立 `build.sbt` 的 2.13.10/3.6.0 声明不得混入同一构建。
- 总则 §4.2 统一命令约定：`hardware/scripts/check TARGET [BOARD] --out DIR [--config CONFIG] [--seed N]`、`hardware/scripts/reproduce MANIFEST --out DIR --offline`；§4.3 环境限制（宿主无 apt/sudo/全局 pip、无 privileged、不挂 Docker socket、Vivado 只读挂载、license 走环境变量）。

## 3. 当前证据与修改文件

当前仓库无 `hardware/`、`.devcontainer/`（P01 已核对）。本任务全部为拟新增：

- `hardware/toolchain/toolchain.lock`：pins、transitive 依赖锁、工具版本、镜像 digest、能力段（`vivado: present/absent + version`、`fpga_capability: ok|blocked`）、**SoftFloat 3e 与 berkeley-hardfloat 的 pinned 来源与构建产物 hash**。
- SoftFloat pinned源置容器锁定dependency workspace，按需在 `hardware/toolchain/` 保存来源/构建规则；本任务用PIC对象构建可加载的 `libsoftfloat.so` 与headers，hash入lock，供P03 ctypes消费，不能把 `.a` 当共享库加载。
- HardFloat只使用Chipyard锁定依赖树中的唯一权威源码，overlay引用一次，不再vendor一份重复编译；保留各自许可证。
- `hardware/toolchain/Dockerfile` 与同目录build overlay；`.devcontainer/devcontainer.json` 引用同一镜像/digest，映射UID/GID。Gemmini权威subtree为 `hardware/gemmini/upstream/`，建立upstream.lock和受控修改导出机制。
- `hardware/scripts/env`、`hardware/scripts/check`、`hardware/scripts/reproduce`（可执行脚本）；`hardware/scripts/README.md`（命令契约与 target 注册表，本文件是任务交付物要求的接口文档）。
- `hardware/configs/README.md`：配置 YAML 格式定义（统一硬件配置入口；P05 起填充实例）。格式至少含：目标描述（topology/numeric keys 预留）、validator 覆盖段（可映射为 `--hw-override`/`--hw-config`）、板级段预留、`schema` 版本字段；解析器对未知 target 引用的配置必须报错。
- `hardware/configs/toolchain-minimal.yaml`（本任务自用的最小配置实例，供 `check toolchain --config` 走通）。

不修改：pipeline_validator 任何文件、plan/README.md 状态由实施者按总则更新。

## 4. 输入输出、接口与不变量

- `env build --locked`：构建镜像（base 按 digest；网络只在镜像构建阶段），内含 P01 锁定的 Python env + sbt/JDK/firtool/Verilator/riscv-gcc；输出 digest 写入 toolchain.lock。
- `env shell`：进入容器（UID/GID 映射，工作目录固定挂载）。
- `check TARGET [BOARD] --out DIR [--config CONFIG] [--seed N] [--case ID]`：在容器内执行真实程序；`--out` 下产出 `manifest.json`、`summary.json`、日志、actual/golden。summary 至少含 `task_id`、`validation_layer`（F/C/R/B/PPA）、`status`、`cases[]`、失败详情、计数；`PASS` 只能由真实断言产生。**`--case ID` 的分派/过滤基础在本任务实现**：target 注册表 `(target, cases[])`，`--case` 过滤或分派到具体 case，未知 target/case 非零报错。本任务只注册 `toolchain` 一个 target；其余总则 §4.2 列出的 target 在注册表中预登记 owner（P03..P24），未实现前调用一律非零失败并打印 “not implemented (owner Pnn)”，不得 echo 成功。
- `reproduce MANIFEST --out DIR --offline`：从 manifest 恢复完整解析配置/输入/工具 hash，离线二次运行；数值与确定性仿真周期必须相同，不依赖暖缓存/网络。
- 不变量：宿主零污染；toolchain.lock 的每个 pin 可追溯到构建日志或上游文件；无 Vivado 时 `fpga_capability=blocked`，但仿真工具链完整可用，`check fpga-synth vcu118` 非零且说明 blocked（owner P23），不影响其他 target。

## 5. 实施步骤

1. 写 Dockerfile（base digest 锁定；安装 JDK/sbt/coursier/firtool/Verilator/riscv-gnu-toolchain 时全部固定版本；从 P01 锁定文件重建 conda env）；构建镜像并记录 digest。
2. 在显式构建/下载阶段获取pinned Chipyard/Rocket/HardFloat到锁定workspace，将Gemmini单份subtree接入overlay、排除Chipyard内重复Gemmini；真实sbt解析依赖并锁transitive与compiler plugin/firtool。不假设某dependencyLock插件必已安装，按实际build graph提供可验证锁定方式。
3. 干净elaborate生成RTL并编译运行一个有输入/输出断言的Verilator最小harness；riscv-gcc编译、链接smoke ELF并验证目标ISA/linker。打印版本或只检查产物存在不算运行证明。
4. SoftFloat以PIC构建libsoftfloat.so/headers并实际加载调用f32_add/f32_mulAdd，记录源/编译flags/产物hash；HardFloat由唯一pinned源成功elaborate primitive。数值政策与完整probe矩阵归P03。
5. 写 `env/check/reproduce` 三脚本与 target 注册表、`--case` 分派基础、manifest/summary 生成与校验函数（`PASS` 仅由断言产生）。
6. 写 `hardware/configs/` 格式说明与最小实例；`check toolchain` target 接 `--config hardware/configs/toolchain-minimal.yaml`。
7. Vivado 能力探测：读环境变量（如 `VIVADO_PATH`）指向只读挂载，存在则记录版本与 license 能力，缺失则写 `blocked`；不自动安装。
8. 离线复现演练：用 `check toolchain --out …` 产生的 manifest 跑 `reproduce --offline`，比对确定性产物 hash。
