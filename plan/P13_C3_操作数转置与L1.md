## 1. 目标与不做

**目标**：实现 Operand/Transpose Adapter 与 L1 请求通路：A/B 四种转置组合、typed view 合法性校验、有效 lane 馈数、按 P10 codec 发出真实 `mem_req`/接收 `mem_resp`、以及 R14 普通输入生命周期（最后实际读取 + 全部声明读者结束后才可复用）。

**不做**：不建立 UCE 可见 RF 分配或专用内部 load 通知事件（已取消的需求；馈数/转置寄存器是内部实现细节）；不实现 MFE/L2 流量与 Group `input_released` 聚合（既有 Group 合同不动）；不实现 STEP 接收/patch 逻辑（属 P14/P16 的命令通路，本任务只消费 descriptor）；不改 `pipeline_validator` 的 view 解析。

## 4. 输入输出、接口与不变量

- 四种转置：A 正常读 `[m,k]`、转置读 `[k,m]`；B 正常读 `[k,n]`、转置读 `[n,k]`；四种组合全支持，验证 view/stride/mask 非对称矩阵。所需流水寄存器/重排缓冲按实际接口建模，内部实现不外泄协议。
- view 校验：allocation/generation、offset/extent/stride、dtype/权限、transpose、有效 mask；非法在可观察副作用（发出读请求、污染馈数）之前拒绝，报 unsupported/size error，不隐式夹带。
- **零维/零 K（§3.1）**：合法空工作由软件前序 lower 为数学定义的输出路径；本模块不发永等 last beat 的数据请求。未规范化非法空请求（extent=0 未经 compiler 规范化）在 view 校验处拒绝；对合法 lowered 空工作的 descriptor 产出定义好的空数据流（或零请求）并让输出路径按 oracle bytes 完成。
- input_ready token 必须对应已 ready 输入或已受理 producer；不能为等任意未来软件信号的步骤发数据请求。
- input_usage 引用：多读者聚合（同 buffer 多链/多步读者全部登记）；仅当最后实际读取完成且全部读者结束后才能复用；释放后立即覆写不得改变任何已发 STEP 的结果；禁止凭 ACCEPTED 或 MAC done 推断可释放。
- `mem_req/mem_resp`：req_id、owner/generation、解析地址、访问类型、byte mask、data/status 按生成 codec；过期/错误 resp（generation 不匹配、错误状态）安全丢弃并结清在途引用，不写入新 owner；合法请求参与实际 L1 仲裁，不以接收命令代替数据传输。
- 读数据在实际 read service 时刻取样；本模块不做提前快照。

## 5. 实施步骤

1. view→物理地址解析器：与 validator resolved-view 同规则（segment、offset、stride、mask），单测覆盖越界/零维/零 K 拒绝（零工作由 compiler lower，不发永等 last beat 的请求）。
2. 四转置数据通路：按 P11/P12 冻结接口馈入；转置=地址序列+必要的重排缓冲，量化其缓冲量并确认不构成第二套 RF 协议。
3. `mem_req/mem_resp` 编解码接线（P10 codec）；在途请求表按 req_id/generation 登记，resp 校验与错误路径。
4. InputRefTable：读者登记/聚合、最后读取判定、释放条件；与 L1 复用（覆写注入）联测。
5. 场景测试：T15（多读者、最后读取延迟、释放后覆写）、T18（跨 context stride/transpose 交错）、四种转置非对称矩阵、过期 resp、input_ready 未就绪。
6. 注册 `boa-operand` target 并产出 manifest/summary；更新 `plan/evidence/P13.md`。

## 6. 验收表

| case | 构造                                                   | 必须观测                                                                         | 失败特征 / 层                             |
| ---- | ------------------------------------------------------ | -------------------------------------------------------------------------------- | ----------------------------------------- |
| PO01 | 非对称矩阵 × 四转置组合（含 stride≠extent view）       | 馈入序列与输出 bytes vs P03 oracle 逐 bit 一致                                   | 转置仅换 stride 未验 extent → 越界读（R） |
| PO02 | 同buffer两读者，读者B最后读取延迟后释放并立即覆写      | 两读者结果不变；释放不早于最后读取及全部读者结束                                 | 提前释放导致结果改变（R）                 |
| PO03 | 旧 generation resp 在 slot 复用后到达                  | 丢弃、不写新 owner、在途引用结清                                                 | 串扰写入（R）                             |
| PO04 | input_ready 未就绪的 STEP 尝试取数                     | 不发出任何数据请求；ready 后正常                                                 | 提前读（R）                               |
| PO05 | 两 context 不同 stride/transpose 交错执行              | 配置不串扰，各链 bytes 正确（T18）                                               | 参数泄漏（R）                             |
| PO06 | 非法 view（extent 越界、权限不符、零维/零 K 未规范化） | 副作用前拒绝并报错；合法 lowered 空工作零请求完成、输出路径 bytes 与 oracle 一致 | 先读后报错；mesh 等空 last beat（F/R）    |

反例边界：以「descriptor 已 ACCEPTED」为理由提前释放 A/B 即违反 R14；引入软件可见 load 完成事件即越权。
