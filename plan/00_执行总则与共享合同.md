# BOA / Gemmini 实施总则与共享合同

## 1. 权威、状态与使用方式

本计划依据 [BOA_Gemmini_Integration_Design.md v0.5](../design/proposal/BOA_Gemmini_Integration_Design.md)，用于将每个子任务交给一个独立模型顺序实施。用户最新决定 > 原方案已确认合同 > 本计划实施细节。原方案 §9.1 未冻结的物理参数、编码和数值特殊值不能在实现中冒充既定事实。

本次只编写计划，不实现 Python/Scala/固件/RTL，不声称新的测试、综合或板测通过。S0/C7-A 的既有实现见[软件实施报告](../design/proposal/BOA_Software_Managed_AM_IR_Implementation_Report.md)；SW-A 与硬件任务均须新证据。每个任务完成都要实际修改并运行所负责路径，不能只再写一份计划。

执行者先读本文件、自己的任务文件、直接前置任务的交接记录及原方案指定章节，再检查当前代码。已被前序任务改变的接口以其经过验证的交接为准；禁止恢复旧实现。文件名为建议新建路径时必须先查找现有等价实现，已有模块优先扩展，不建第二套。

### 当前仓库证据（2026-10-28，只读核对）

- `pipeline_validator/tile_group.py` 的构造函数创建一个 `SharedAmManager` 并注入所有 Tile；`tile.py::ComputeTile` 已有本地 manager 构造路径。
- `shared_am.py::request` 已是一次申请、挂起、slot_free 唤醒并有 bundle/FIFO；不要重新实现 TRY/BUSY 轮询。
- `shared_am.py::_allocate_lease` 仍设置 `bound_engine=slot.group`；`tile.py::_engine_for_queue` 返回单个 `tile.boa`。
- `boa_numeric.py::matmul_f32` 与 `test_boa_am.py::_oracle` 仍待逐 MAC FP32 RNE 迁移；生产模型与 oracle 不能同构复用。
- `shared_am.py::commit_step` 在 FINAL commit 写 `chain_done`，`release_final` 稍后才 `_free_slot`；必须修正终态顺序。
- 源及 executable 为 v4；当前 CLI replay 参数是 `--compiled-file`，不是 `--compiled-input`。
- 当前没有 `hardware/`、`.devcontainer/` 实现。下面的硬件路径/命令是本计划要求交付的接口，不是已存在能力。

## 2. 逐任务执行与状态规则

默认严格按 P01→P29 顺序运行；这是一条拓扑有序、避免共享文件并发写入的保守路径。各任务另列最小依赖，可据此安排文件不重叠的工作，但不得绕过 gate。一个任务一个模型；禁止同时启动依赖尚未通过的任务。

状态：`未开始`、`进行中`、`阻塞`、`通过`。历史 S0 通过不意味着 P01/P09 新基线通过。阻塞必须写明缺失输入、已完成可达工作、失败命令/证据及解锁条件；后续依赖任务不得把阻塞当通过。依赖检查、实现、真实 smoke、必要回归、文档同步与交接都属于同一任务。

每项完成后，新建或更新 `plan/evidence/Pnn.md`（实施时创建，本次不生成空证据）：

1. 任务 ID、状态、日期、输入任务及其证据路径。
2. source/repo hash、dirty diff hash、工具版本/镜像 digest；不能只写 commit，忽略未提交代码。
3. 修改文件、接口/配置/ABI 变化；说明删除的旧路径和调用方迁移。
4. 原样命令、exit status、日志及 manifest 路径；actual/golden bytes、seed、trace/波形、资源与周期报告。
5. 每个验收 ID 的真实层级 F/C/R/B；未运行项及原因，不使用笼统“全通过”。
6. 不变量结果、残余风险、下一任务可直接使用的 API、配置和产物路径。
7. 若原方案仍描述旧实现，同步相关文档的当前状态，保留历史数字的历史标签。

模型交接提示模板：

> 只实施 `plan/Pnn_….md`。先读 `plan/00_执行总则与共享合同.md` 和直接前置的 evidence；核验依赖已通过。复用仓库约定，完成该任务的全部范围、真实 smoke 和回归，更新受影响文档以及 `plan/evidence/Pnn.md`，再更新索引状态。不要顺带实施下一个任务；不得以 mock、跳过、fallback 或只添加测试文件宣称完成。

## 3. 全任务不可改变的合同

### 3.1 拓扑、配额、请求与 affinity

- AM 属于 **Compute Tile**：每 Tile 4 groups×2 slots=8 槽，Tile 间独立；group 不是 engine，也不是 Tile Group。
- 每 context 最多 2 live leases，跨本 Tile 所有 engine 统计。默认 4 contexts，验证 1/2/4/8；一个 hart 不等于一个 context。
- 静态 bundle=程序最大同时存活链数，≤2；FINAL accepted 后该链不再计静态未完成链，但物理 lease 直到 slot_free 才归还。
- fresh 只在完整 bundle 能放入未预留空槽时授予，fresh FIFO 不插队；continuation 只用自身预留或等待自身已受理 FINAL 的链。quota=2 本身不是无死锁证明。
- 同 logical_am 有任何 live lease 时不能重授予；未受理 FINAL 是永久合同错误，已受理 FINAL 是可挂起条件。
- AM_REQUEST 一次发出；PARKED 不占 slot/quota/generation；WAKE 交付已授予 lease，不是重试许可。每 owner 最多一条挂起请求。
- 授予原子取得 slot/quota/ChainTable/current+next mailbox 和已准入输出绑定；不得占槽后再等元数据。
- slot 按 `(group,index)` 首个空闲选取；engine 按 live-handle 数最少、平局最小 ID 选择，独立于 group。授予后 affinity 至 slot_free 不变；忙时等原 engine，禁止迁移。
- 单 engine 可服务超过两个 live handles；每 engine 同时最多一个 executing step。两链不因同 context 产生额外依赖。

### 3.2 数值、内存与有限资源

- BF16 输入；每 tile_k 块从 +0 开始按 k 递增做 `fma_f32_rne`；INIT 首块覆盖 AM，后块用 `add_f32_rne`，不能将整个 step 先汇总再一次相加。
- 默认 ArrayRows/Cols=16/16，TileM/N/K=16/16/8；tile_k 是数值参数，必须进入 fingerprint，不能为了吞吐偷偷改成16。
- mask 无效元素不执行 MAC，不能用补零 MAC 代替旁路；INIT 不读旧 owner 垃圾。
- 支持 f32、BF16、INT8 最终输出；中间不缩位、不量化、不激活。bias/scale/ReLU/clip/quant 只在 FINAL 一次应用。
- NaN 编码、INT8 NaN/Inf 策略、后处理各次舍入在 P03 通过独立 oracle/SoftFloat/HardFloat 证据冻结；不能假定当前源支持 i8 就已有数值实现。
- 普通输入生命周期：descriptor accepted 不表示 A/B 已读；最后实际读取、全部读者与在途访问结束后才复用。不增加软件可见 RF slot/load 事件。
- 每个真实 FIFO 独立 O+R≤Q；发射前预留最小不可暂停块全部输出，arrival 只是 R→O，下游有保障后 dequeue 才释放该层容量。
- RMW 地址互锁覆盖 read→adder→writeback；bank 与 adder 吞吐独立；drain 有公平端口服务。

### 3.3 完成、故障与事件

成功 FINAL 必须满足 `compute_done ≤ step_committed ≤ output_visible ≤ slot_free ≤ chain_done ≤ UCE event`；非 FINAL 完成为 step_committed，不写 L1。

事件槽按 Tile Program 静态事件数在 context admission 时分配，身份含 `(ctx_id,epoch,event_id)`；槽的内容关联 handle/generation/seq/kind。AM grant 不取得也不等待完成事件槽；terminal 环仅诊断、可覆盖并计溢出，不承载 correctness。

必须通过 Q09：`FINAL(slot0) → ALLOC(slot0) → await(旧事件)`，没有中间 reap；旧链自主 free，新申请获授予，旧事件仍可 await。低层 WAIT/check-register 的竞争测试在事件硬件和真实 UCE 层完成，**不新增源级 CFG/TRY/await_any**。

context return 后有 FINAL drain 则 FINISHING；缺 FINAL 是错误。fault/reset/cancel 必须停止新提交，结清旧内存/结果引用后回收并发布失败终态，不能将 timeout 当回收证明；旧响应不得污染新 generation。有限 ID 回绕须 quiescence/背压规则，不靠“大位宽永不回绕”。

### 3.4 联仿与 UCE 单一权威

- validator 是仿真 cycle 权威，ByteStore 是外部存储字节权威；功能/周期/RTL backend 中只有一个维护 AM。
- cycle c：到期响应→一次 RTL edge→采样请求/完成→UCE-local completion→UCE 发射供下一 edge；新请求最早后续 memory service 返回。
- A/B 在实际读服务取样，写服务完成后更新 ByteStore；不能接受 descriptor 时先把 A/B 复制给 RTL，也不能 read_view 就算实际端口访问。
- C ABI 进程内 shared library、按 beat 批量交换、版本/能力检查；不能逐命令起子进程、逐 byte Python 回调或跑完整矩阵后回填时序。
- Python UCE 与 Rocket 对同一 Task 互斥；不支持的指令闭包明确拒绝，不能回退 Python 执行。
- Rocket 真实执行固件及 RoCC；GRANTED/PARKED/FULL 都在有限时间返回。WAIT_AM 不重发 AM_REQ；位图观察不驱动释放。

## 4. 跨模型接口与文件 ownership

### 4.1 统一来源

- P02：`hardware/toolchain/toolchain.lock`、Dockerfile、build overlay、devcontainer、统一脚本分派、manifest 基础结构。
- P03：`hardware/boa/reference/` 独立 oracle 与 golden vectors；数值冻结记录。生产模型不能直接调用该 oracle 以替代自身实现。
- P04：用固定拓扑语义标识更新target identity，旧Group共享artifact立即拒绝；不是可切回旧实现的用户配置。
- P05/P06：配置通过既有解析器统一映射。P05落地arrays_per_tile、array_rows/array_cols、tile_m/tile_n及其fingerprint与真实调度消费者，移除旧OPA专用别名。原方案数值tile_k在软件配置中拼为 `engines.boa.numeric_tile_k`→`boa_numeric_tile_k`，避免混同WorkloadConfig.tile_k；numeric_profile由P06一起落地。Scala的TileK与wire字段须明确映射，不能产生两份独立K参数。
- P04/P05阶段已生效的拓扑/几何必须即时更新fingerprint；序列化若改变则即时升版。P06按原方案§9.1执行数值breaking ABI/schema升级并重生成受影响artifact，消费实际前序版本而不硬钉v5。P08新增epilogue/transpose可执行字段继续按严格规则升级；旧版本与新版错target分开拒绝，无fallback。
- P10：`hardware/boa/protocol/boa_protocol_v0.json` 为拟新增权威 wire/descriptor schema，生成 Scala/C/Python codec；数值编码/位宽在该任务评审及验证后冻结，本计划不先编造编码。软件 artifact 版本与 wire ABI v0 是不同版本域。
- P11/P12：`hardware/gemmini/` 适配器与必要上游修改；不把 BOA scheduler 放进 upstream。
- P14/P15/P16/P17：各自 allocator、event、AM service、epilogue/drain 模块；P18 为单阵列 top 集成 owner。
- P19/P20：C ABI 与 validator memory/backend 接线；P22 是 ControlBackend/固件接线 owner，不建立通用第二套 scheduler。
- P23/P27：同一 VCU118 harness 的配置、约束、实现报告；不复制另一份板级系统。

同一文件可能由顺序任务继续修改，禁止并发改。接口变化在 evidence 中列 producer/consumer/codec/config/docs/fixtures 全部调用方；修改导出符号前查 references。新 Scala 文件精确包名、测试 runner、类名由已有 build graph 决定；任务中的新路径是落点建议，不是假称已存在。

### 4.2 构建和验收入口（待实现）

P02 提供真实 `hardware/scripts/env` 和 `hardware/scripts/check` 分派器；各任务增加自己的真实 target。尚未支持的 target 必须非零报错，不能 echo 成功或空跑。统一参数约定：

```text
hardware/scripts/check TARGET [BOARD] --out DIR [--config CONFIG] [--seed N] [--case ID]
hardware/scripts/reproduce MANIFEST --out DIR --offline
```

- 所有 check 在锁定容器内运行；`--out` 输出 `manifest.json`、`summary.json`、日志、actual/golden、trace/必要波形。
- summary 至少含 task_id、validation_layer、status、case IDs、失败详情、计数、资源归零结论；`PASS` 只能由真实断言成功产生。
- software/F、cycle/C、RTL/R、board/B、PPA 分开记录。FPGA 合成成功不等于板测 B。
- 统一 target：`toolchain`、`numeric`、`shared-am-functional`、`two-slot-progress`、`shared-am-cycle`、`single-array`、`validator-cosim`、`rocket-uce`、`rectangular`、`multi-array`、`fpga-synth vcu118`、`fpga-board vcu118`。模块细分 target 在负责任务交付；不能用同名 target 混淆软件/RTL层。
- 配置文件统一为 `hardware/configs/*.yaml`；P02 定基础格式及 `--case ID` 分派/过滤机制，P05/P10 接通软件/协议字段，各后续任务注册自己的真实 target/case。manifest 保存完整解析配置，而非只存路径。
- P04/P05/P07保持可仅用现有软件环境独立执行；P09统一注册其shared-am-functional、two-slot-progress、shared-am-cycle容器runner。numeric归P03、numeric-profile归P06、soft-conv归P08，single-array归P18；其他模块target在各任务注册，不能以登记owner代替实现。
- `reproduce` 从 manifest 恢复配置/输入/工具 hash；离线二次运行在数值与确定性仿真周期上相同，不能依赖暖缓存或网络。板测需实体板卡，不要求与 validator 周期相同。

### 4.3 环境限制与板级阻塞

候选 Chipyard/Gemmini/Rocket pins 以原方案 §1.4 为起点：Chipyard `e02074414158c85059c1dcb231ff2f8941254b9a`，Gemmini `25809f78323a729ef76fb68f3cedd8a24da2942b`，Rocket `c7aabd2823d3d001a7a9e8a982bb65d6cb7c9bdf`，Scala 2.13.12/Chisel 6.5.0。必须真实构建后锁 transitive dependencies，不宣称候选已验证。

宿主禁止 apt/yum/sudo/全局 pip、系统配置修改、privileged、Docker socket 挂载。Vivado 由用户提供、只读挂载，版本与 license 能力在 P02/P23 验证，密钥不入仓库。USB-JTAG 驱动/udev 由用户自行安装；只在实际烧板命令显式映射必要设备。

无 Vivado/license 时 P02 的仿真工具链仍完成，FPGA 子能力标阻塞；P23 不能通过。无板卡/JTAG 时可完成综合与板测程序，但 P24/P28 必须阻塞，不能用仿真替代。最终 P29 不得把未跑 B 项记通过。

## 5. 验证纪律与计数解释

现有软件 gate：从仓库根目录运行 `conda run -n elenor-validator pre-commit run -a`，再 `conda run -n elenor-validator python -m pytest pipeline_validator/tests/ -q -n 4`；局部任务先运行相关测试和真实 CLI smoke，整体 gate 在 P09/P29 集中运行。不要为了重写预期而固定新周期常量；报告拓扑/数值改变造成的新测量。

所有 numerical runs 为 full_memory/ByteStore，有真实输入数据和独立 golden。split-K 中未实现数值的 EVU combine 只能证明调度/资源，不能拿最终 C 宣称数值通过；应另用 BOA-only fixture 验完整 bytes。

F03 的 `request=grant=ALLOC`、`final=slot_free` 只用于**全部请求成功授予且全部链成功 FINAL**的运行。取消/ERROR 故障用独立分母：被拒绝请求、已挂起取消、已授予故障回收分别记账；闭合运行检查 `park=正常wake+挂起cancel`，不可对混合故障场景硬套成功恒等式。Q08 的双 Tile 是 RTL 隔离 harness，FPGA 仍只有一个 Tile，不增加多 Tile 板级范围。

测试必须检查用户可观察行为：C bytes、事件偏序、无副作用、容量/所有权、进展和错误收尾。禁止仅测试源码字符串/转发/mock 回显；保留合理确定性边界回归。若代码或硬件不符合合同，修实现，不放宽 oracle 或跳过困难案例。

## 6. 明确非目标

源级 CFG/TRY/通用 DAG、K-step 跨 engine 迁移、同 C 多 engine split-K、跨 Tile AM、AM spill/抢占/atomic、FP32/INT8 输入 Matmul、硬件 Conv、专用软件 RF/load 事件、多 Tile FPGA、PCIe/XDMA、HBM、partial reconfiguration 不在本计划。已有无关功能不得删除。

WS/OS、特殊值策略、wire 编码、物理端口/流水/宏、Vivado 版本由指定任务凭证据冻结；其余已确认边界不能重新投票。100 MHz 是首版目标，WNS<0 的实现不得验收；若必须降频或改流水，记录偏离、重新验证受影响路径，不把推导吞吐/资源当实测。
