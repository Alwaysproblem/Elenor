# BOA / Gemmini 需求覆盖与验收分配

## 1. 使用规则

来源：[总体设计 §8–§9](../design/proposal/BOA_Gemmini_Integration_Design.md)。本表是**计划覆盖，不是通过记录**。每个任务实施后在自己的 `evidence/Pnn.md` 记录case、真实manifest和验证层级；P29汇总最终状态。

层级：**F**=功能模型，**C**=周期模型，**R**=RTL/RTL联仿，**B**=实体FPGA板。F01–F08中的字母F是原方案验收编号，不代表“功能层”。软件S0历史通过不能替代新的R/B层。下表任务链接统一通过[总索引](README.md)进入。

默认所有行状态为“待实施/待新证据”。“最低层”保留原方案要求；计划中的更高层重复验证不是替代低层，也不是声称已完成。矩形/多阵列板测留到P28，P24仅关闭单阵列适用子集。

当前已有 [P01 基线证据](evidence/P01.md)、[P02 工具链证据](evidence/P02.md)、[P03 数值证据](evidence/P03.md) 与 [P04 拓扑证据](evidence/P04.md)：T-P02-1–T-P02-7、N-P03-1–N-P03-11 与 P04 的 Q08a/Q08b/Q09/ID-P04-1/2/RPT-P04-3 已通过，包含禁网冷构建、三方 bits/flags、per-Tile AM 隔离与确定性产物 hash 对比。这不关闭下表的完整 BOA、真实 UCE 或 FPGA T/Q/F/R 系统需求；Vivado/板级能力仍无通过证据。

[P05 多 engine 与固定 affinity](evidence/P05.md) 已通过软件 F/C 层 T04/T05/T06/T20 子集、原子授予/记账、旧 target 拒绝及全量回归（716 passed / 1 skipped）。1/2/4-engine trace 实测并发峰值分别为 1/2/4；单 engine 四 live handles、双 engine 八 live handles 均保持每 context quota 2。该证据不关闭下表要求的 RTL、真实 UCE 或 FPGA 系统复验，尤其不能将软件 4/4 handle 分布当作 F05 板级通过。

[P06 数值与 artifact 迁移](evidence/P06.md) 已通过生产 F/C 层 V-P06-1–7、PERF-P06-8、REG-P06-9：50项向量/负例/定向检查，完整1114112 bytes与P03独立reference相等；v4版本与v5错target分别拒绝；容器71断言、离线55产物MATCH，全量769 passed / 1 skipped。P08病例仅观察pre-epilogue AM，不关闭INT8/后处理；也不关闭T07等要求的RTL复验、P07终态或任何实体板级项。

## 8. 最终关闭规则

P29逐行填入真实case/manifest与状态。必达项未满足、板卡或Vivado不可用、未验证的NaN政策、只有单阵列无矩形/多array，均不能宣布完整交付。明确延期只限原方案非目标；不能把实现困难改写为新的延期。

本计划的结构检查只证明任务/依赖/链接/需求覆盖完整，不证明任何未来实现已通过。未来每个实施模型必须遵守[总则](00_执行总则与共享合同.md)的真实smoke和交接要求。
