## 4. 输入输出、接口与不变量

- 事件槽：数量=Tile Program 静态事件数（每个 typed Matmul 事件名唯一），context 绑定/admission 时分配并经 admission 校验；身份 `(ctx_id, epoch, event_id)`；内容关联 handle/generation/seq/kind。**AM 授予与唤醒从不等待事件 await/reap；授予路径无事件槽请求线**（P10 lint 的运行时复核点）。
- WAIT/check-register：检查终态并登记等待者必须原子；事件先到立即满足；已处理粘性事件从 wait_set 移除；禁止忙循环。T16 竞态集：事件早到、WAIT 边界、多事件乱序、park 与 slot_free 同拍、cancel 与 grant 同拍——均无丢/重复唤醒。
- EVT_STATUS 电平位图非破坏性读；EVT_TAKE 取 lease 唤醒记录或事件终态；REC_REAP 可选退休（context 退休时自动），不影响 AM。旧链事件保留到 await 或 context 安全退休；同 logical_am 新链事件不覆盖旧链事件。
- terminal 诊断环：有界、满则覆盖最旧并计溢出，仅诊断不参与 correctness（与软件 `terminal_capacity` 一致）。
- fault/reset/cancel停新提交，FAULT_QUIESCING结清全部旧引用，安全回收slot/quota，再发布ERROR/CANCELLED终态；不能终态先于回收。迟到响应不污染新代但仍要结清旧引用；reset各slot generation换代，不物理清零。
- epoch/ID 复用：仅当命令、输入引用、AM 访问、事件引用全部安全处理后才复用 context ID/epoch；无后台 detach。
- FINISHING：context 返回时已提交 FINAL 尚在 drain 则 FINISHING，收尾不依赖已返回 context 再执行；缺 FINAL 的活链是协议错误。

## 5. 实施步骤

1. 实现有界事件槽/位图/wake mailbox；根据P10容量选择寄存器或BRAM，不预设所有程序事件均塞寄存器。
2. check-and-register在同一序列化点生效，不要求多周期BRAM查表物理上“一拍做完”；测试事件早到/同时到/登记后到、等待集合更新。
3. CANCEL先取消挂起并阻止新提交；旧owner成为tombstone直至所有响应/引用结清。迟到交付禁止唤醒已取消context，不能仅drop而泄漏引用。
4. QuiesceController接有界受控memory/compute/RMW/drain端口模拟在途握手，证明停发→quiesce→slot/quota回收→失败终态。此处是事件/回收控制RTL模块验收，P18接入真实数据路径才关闭完整故障场景。
5. Q09模块序列：FINAL已接受→ALLOC同slot挂起→受控drain完成/free→新grant→旧event仍可await；不依赖P17先实现。P18/P22/P24再以真实output背压执行完整Q09，不用本模块结果冒充系统闭环。
6. Q08双allocator/event实例验证故障/满槽隔离；不声称其中含完整Tile数据通路，不扩大板级范围。
7. 注册 `boa-event` target；更新 evidence（含 T16 竞态矩阵逐项结果、Q09 时序 trace）。

## 6. 验收表

| case        | 构造                                                     | 必须观测                                                                  | 失败特征 / 层                      |
| ----------- | -------------------------------------------------------- | ------------------------------------------------------------------------- | ---------------------------------- |
| PE01 (Q09)  | FINAL(slot0) 背压→ALLOC(slot0)→await(旧事件)，无 reap    | 新链在旧链 slot_free 后获授予；旧事件仍可 await；无挂死                   | 授予等 reap（R）                   |
| PE02 (Q05)  | PARKED 后 fault/reset/rebind                             | 永不唤醒；bundle 归还；迟到交付被丢弃                                     | 死请求唤醒（R）                    |
| PE03 (T16a) | 事件先于 WAIT 到达                                       | 立即满足，从 wait_set 移除，无忙循环                                      | 忙循环/重复交付（R）               |
| PE04 (T16b) | park 与 slot_free 同拍；cancel 与 grant 同拍（定向序列） | 无丢/重复唤醒；状态机一致                                                 | 丢唤醒（R）                        |
| PE05 (T17)  | slot 复用后旧 generation 结果/完成到达                   | 不影响新 owner；旧终态仍可观察（槽保留期内）                              | 覆盖新链事件（R）                  |
| PE06 (T19)  | FINAL drain 中 context 返回；缺 FINAL 退出               | FINISHING 自主收尾；缺 FINAL 报协议错误                                   | 缺 FINAL 静默成功（R）             |
| PE07        | 四类端口在途握手的模块级fault注入                        | 停发→quiesce→安全回收→失败终态；旧引用归零，完整新C验证归P18              | 终态早于free或timeout强清（R模块） |
| PE08 (Q08)  | Tile0 fault+满槽                                         | Tile0 与 Tile1 的 slot/quota/事件/terminal 计数互不影响；板级范围声明不变 | 跨 Tile 泄漏（R）                  |
| PE09        | terminal 环溢出                                          | 覆盖最旧+溢出计数；correctness 判定不受影响                               | 环满阻塞 AM（R）                   |

反例边界：任何以「加一个源级 await_any/try 分支」解决竞态的方案违反不扩源 CFG 合同；事件槽计入授予资源即违反 P10 lint。
