## 1. 目标与不做

**目标**：在 P11 冻结的单 dataflow 上实现并验证 16×16 方形 mesh 全链路：skew/tag/last/drain、配置切换安全边界、AM 端延迟接收不丢结果；量化并冻结「最小不可暂停输出块」合同，供 P10 schema 容量字段与 P16 发射预留消费；交付第二种方形配置。

**不做**：不实现矩形（P25 独立推导 row/column skew，**不允许以删除 square assert 的方式蒙混**）；不实现 AM/RMW/credit（P14/P16）；不接 UCE/Rocket（P21/P22）；不重复 P11 的 PE 数值对拍（复用其向量与结论）。

## 2. 前置与输入

- P11 通过：dataflow 冻结、PE FP32 贯通、PE→mesh 排空接口字段已定义。
- P02/P03 前置沿 P11；P10 的 schema 若已含输出微块容量字段则直接引用，若需新增字段按 P10 的版本域规则走变更，不静默改 JSON。

## 4. 输入输出、接口与不变量

- **不可暂停输出合同**：对每层接收FIFO选择统一单位（beat或byte），计算 `sum(所有已发射且不能暂停微块的尚未到达beats)`；字节为beats×每beat有效宽度。skew/latency决定并存在途块数量，不额外把“行数×排空拍数”重复相乘。输出 `min_nonstoppable_outputs` 及单位/最大并存在途数，供P16预留；不能只看当前空位或给Valid强加ready。
- **完成边界**：本层只发布「mesh last + 保护路径接住」的原始 compute_done 信号；它不是 step_committed（AM 提交边界在 P16），不得提前。
- **状态保留**：保留 MeshWithDelays square assert、`n_simultaneous_matmuls` 最小值约束、PE c1/c2/propagate/tag 寄存器；「禁用 double issue」不得实现为把参数设 1 或删寄存器；每 engine 同时最多一个 executing step 的限制由 BOA 侧调度（P16 仲裁）承担，不动上游状态。
- **配置切换**：在P14 mailbox接受descriptor快照，与mesh真正issue/切换配置分离；RUNNING期间仍允许一个next-step mailbox。仅mesh issue要求安全边界，不禁止整个系统提前ACCEPTED下一步。
- **零维/零K**：软件前序P06/P08/P09定义合法空工作/输出路径；mesh入口不发空微块，未规范化零extent拒绝。若lowered路径完全绕过mesh，不要求本模块伪造compute_done/输出bytes；完整结果在P18验证。
- 下游延迟时已获预留的全部输出必须受保护，有限容量耗尽后阻止后续微块issue；不承诺无限持续发射下任意长背压仍有无限接收能力。

## 5. 实施步骤

1. 量化 `min_nonstoppable_outputs`：按 P11 冻结 dataflow 推导在途结果上界（输入 beat 数、排空拍数、skew 深度），用仿真验证实测上界 ≤ 合同值；把数字回填 P10 schema 容量注释/字段（走 P10 版本规则）与 `hardware/configs` 单阵列配置。
2. mesh 级审计：skew/tag/last/drain 全路径走查，确认与 P11 PE 排空接口衔接；记录每拍输出宽度（16 FP32 lane）。
3. 第二方形配置 elaboration（如 32×32 或 8×8，按资源与上游参数可行性选择并记录理由），确认同一 adapter 复用。
4. mesh 数值测试：完整 tile step 输出 bytes vs P03 oracle；AM 端延迟接收注入（0/N 拍）；配置切换正反例。
5. 注册 `gemmini-mesh` target，输出 manifest/summary（case、向量统计、`min_nonstoppable_outputs` 实测 vs 合同）。
6. 更新 `plan/evidence/P12.md`。

## 6. 验收表

| case | 构造 | 必须观测 | 失败特征 / 层 |
| --- | --- | --- | --- |
| PM01 | 16×16的各tile_k贡献块 | 每块FP32 partial逐bit等于P03对应块golden，不把mesh输出当已累加AM | 块舍入/顺序错误（R） |
| PM02 | 第二方形配置和尾块 | partial正确且输出量上界成立 | 重用方形常数导致越界（R） |
| PM03 | 对已预留微块延迟下游消费；随后再次请求issue | 已发结果无丢/错tag，保护容量不足则后续不发射；compute_done不等于AM commit | 加ready假设停阵列（R） |
| PM04 | 本任务harness按合同实际预留有界buffer | 各微块/在途组合不溢出；向P16交接单位和上界，不以尚未实施P16为当前通过条件 | 容量无上界或产生依赖环（R） |
| PM05 | 新descriptor入next mailbox，旧块在途时试切mesh配置 | descriptor可先快照；mesh切换推迟到安全边界，旧结果不串扰 | 把accept与issue混成一个门（R） |
| PM06 | 上游状态审计与多块交替运行 | 保留所需状态，换块/换tag数值正确；源码审查辅助而非字符串测试 | 盲设参数为1/删寄存器（R+审计） |
| PM07 | 空工作不发mesh微块，未规范化零extent注入 | 入口按规范拒绝或旁路，不能等last；P18验证旁路完整输出 | mesh挂死（R） |

反例边界：以矩形输入跑本 harness 属非法用例（矩形归 P25）；把 PM03 的延迟接收实现成给上游加 `ready` 即违反 §1.4 第 3 条。

## 8. 产物、交接与停止条件

- 产物：mesh 适配层、mesh spec 测试、`min_nonstoppable_outputs` 合同（回填 P10/configs）、`gemmini-mesh` target、evidence。
- 交接：P13 消费馈数/输出接口；P16 消费不可暂停输出合同与原始 compute_done；P18 集成门核对 PM06 状态保留清单。
- 停止条件：延迟接收丢结果；需要删 assert/改 tile_k 才能通过；`min_nonstoppable_outputs` 无法给出确定上界。
