## 1. 定位、目标和 First Silicon cutline

W7 是**仿真 Host 侧验证资产**，不是片上硬件，不取代任何执行 owner：按 r5 §18.2.1，Host 只维护只读影子记分板与记录，不得代 RTL 产出计算结果、完成信号或推进被测 credit。交付四类资产：

1. **统一 trace 捕获与重放**：边界日志逻辑 schema、捕获窗口、完整性判定、单侧重放（VER-22）。
2. **checker 集合**：格式／偏序／守恒／独立数值 oracle／终态终止／重放门／manifest 门（VER-04/05/08/15/16/20/26）。
3. **68 用例完整追踪表**：T-01～T-68 每项主责 W 包＋验证层＋具体输入与 oracle（§8.1），NEST 语料映射与 **N05→T-20 裁决**（§8.2），无遗漏、无 dangling。
4. **性能口径**：P0/P1/PN/PS 同工作量、同时钟边界（PERF-01～07、OBS-12）；不做 PPA、不做多 VME 利用率估算（r5 D-29、§22.3）。

§22.1"验证证据／联合仿真环境／性能报告"三个交付物的生成规则由本文件定义。

## 3. 微架构和状态机

### 3.1 Host trace 记录逻辑 schema（编码由后续规格冻结）

Host 经 W1 adapter 被动监听边界端口（VER-12），每条观测一行版本化紧凑记录，字段：

| 字段组 | 内容                                                                                                                                                                                                                                                                                      | 约束／用途                                                                                                                   |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 头     | schema_ver、window_id、protocol（逻辑通道命名空间）∈{CTRL,EVENT,PROGRAM,MEMORY,DEBUG}、dir∈{req,resp}                                                                                                                                                                                     | protocol 命名空间与 W1 逻辑通道一致、各自独立预算；DEBUG 可丢                                                                |
| 时序   | cycle、phase、seq                                                                                                                                                                                                                                                                         | (cycle,phase) 在 W1 时间权威内唯一定位一个采样点；seq 窗口内严格单调、无回绕；seq 断档＝窗口不完整                           |
| 身份   | TaskKey(root_launch_generation, GridInstanceId, task_id)＋physical_tile（路由单列）；ContextKey(tile_id, ctx_slot, ctx_generation)，代际分域：ctx_generation 与 arena_alloc_gen／program_epoch／profile_gen／run_gen 各自独立、不得互推；op_seq、subop_id、txn_id、fetch_epoch、region_id | 与整合合同一致；vme_instance 仅 W3 内部／验证可见，软件不可观察（T-68）；片上只携紧凑 ID，详细映射在 Host manifest（OBS-10） |
| 握手   | port、valid、ready、accepted                                                                                                                                                                                                                                                              | 仅 valid&&ready 记 accepted；valid&&!ready 期间 payload 稳定作为断言输入（§18.3）                                            |
| 数据   | len、payload_hash、blob_ref                                                                                                                                                                                                                                                               | blob＝Host 被动观测到的实际端口 payload 字节（内容寻址），不是 RTL 额外只发 hash；hash 为派生校验值，仅凭 hash 不可重放      |

唯一性规则：(window_id, protocol, port, dir, cycle, phase) 至多一条 accepted 记录（同拍同口的 req 与 resp 各自至多一条）；功能事件另带 R1 序号（见 3.2）。
原始记录不量化：边界日志只保存整型 cycle/phase/seq 与 payload 原字节，时间换算只发生在派生展示视图。µs 路径＝`cycle_to_us` 的 round(cycle×cycle_ns/1000, 3)（`../../../pipeline_validator/trace.py:213-216`；cycle_ns＝1000/clock_mhz，`../../../pipeline_validator/config.py:366-368`），.001 µs 粒度＝1 ns，仅当 cycle_ns 为整数 ns（如 1000 MHz→1 ns）时单次换算精确；ns 路径（Perfetto ts 以 ns 记）cycles＝ts_ns×clock_mhz/1000，仅 1000 MHz 时 ts 数值与 cycle 相等。两路径都不是权威：排序、身份与偏序判定一律取原始 seq/cycle 字段，禁止用展示 ts 排序或对拍。

相位模型（随 W1 冻结）：P1＝边沿前双向 valid&&ready 快照；P3＝仅提交本接受集；P4＝Python 唯一时间推进，被测侧（RTL/C++）不回调 Python、不执行 P4。W7 记录与判定的 phase 语义与此一致，checker 不得自造第二个相位含义。

### 3.2 可靠性分级与正常模式约束

- **R1 功能事件**（task/phase/completion/fault/credit/lease/grant）：可靠、有序、不丢；checker 视 R1 缺失为 FAIL，不做"可能丢了"豁免。
- **R2 诊断**：片上小 FIFO 流式暂存（OBS-15），满则丢新或停采并置 dropped 计数＋窗口不完整标记；不得阻塞 issue、state_free、唤醒、终态或故障处理；功能消息绝不走 R2。
- **控制事件可靠性与 debug 副本分离**：控制／功能事件的可靠交付属 R1 合同通道；同一事件在 debug FIFO／展示日志里的副本属 R2 可丢路径。checker 判定只以 R1 为准，R2 丢副本不影响功能结论。
- **正常模式**：片上不留存历史、不产生 HBM 日志写（OBS-14）；联仿 Host 对端口的被动记录不属于片上留存，不违反本条。debug 导出扰动单独计量，不计入正常性能（OBS-05）。

### 3.3 捕获窗口与单侧重放（VER-22）

- **完整窗口清单**：schema 版本、方向、身份、采样／握手时序、完整 payload 或可取回 blob、初始内存／状态快照、映像（hash＋长度）、seed 与背压／延迟配置。摘要不能重建数据（OBS-18）。
- **启动 epoch 显式化**：窗口自带 startup epoch 标记（窗口起点、时钟对应、是否包含启动段）。validator 默认 trace 会剔除 Profile 初始化（`../../../pipeline_validator/trace.py:197-209`，OBS-13），该剔除只允许作用于派生展示视图；CS1 原始边界日志不得把旧行为当作完整启动记录——启动段（Profile init、程序首装、复位后首个冷启动）必须完整落在窗口内，或显式标注"本窗口不含启动"并在 manifest 记差异（关联 T-58 复位后冷启动、T-49）。
- **完整性判定（重放门）**：seq 连续 ∧ 全部 blob_ref 可取 ∧ hash 匹配 ∧ 初始快照与映像在列 ∧ **封窗记录在且校验通过**（首/末 seq、记录数与实际一致；记录实际到达封窗**声明的结束边界**——可以是 run 终态，也可以是显式声明的捕获终点，如已知死锁／中途 assertion 故障窗口的声明结束 cycle，DUT 允许仍有 pending；gap/quota 状态为无缺口）→ 判"可完整重放"；任一不满足——含未经声明丢失末尾、前缀仍连续的情形——→ 显式 verdict"不可完整重放"，仅保留可用摘要（T-67）。**"窗口可完整重放"≠"任务已结算/成功"**：run/Task 终止与 pending 判定归 C5（VER-22 的失败窗口重放正是 C6 的合法输入）。
- **单侧重放**：以窗口内记录的请求驱动被测 RTL 重跑，实际发出的请求须与日志身份匹配才回放对应响应；比对重放 trace 与原窗口在合同口径（偏序＋终态＋握手合法）上等价。CS1 出口判据（5）要求：完整 Host 捕获窗口的**已知故障**可单侧重放；正常模式无日志不构成失败。双侧重放不在本轮承诺。

- **捕获配额**：Host 捕获受配置化 file quota／容量限制；达到配额即停止写入并把未写部分标记为 gap（窗口不完整），不得无限占用存储。

### 3.5 性能采集口径

- 时间：Python `Simulator` cycle 为唯一权威，1 tick＝1 RTL 核心周期（VER-18）；周期校准另做专门实验，以 RTL 为周期真值。
- 键映射：RTL 报告至少覆盖 OBS-12 同名键（`cycles/completed/utilization/credit_invariant_ok/stall_breakdown/stall_categories/traffic/events/memory/scheduler/resources/profile/arenas/task_leases/checks`；validator 现有字段见 `../../../pipeline_validator/report.py:29-49`）。
- stall：以 12 成员 `StallReason` 为基线（`../../../pipeline_validator/pmu.py:15-29`：NONE、WAIT_EVENT、WAIT_OPERAND、STREAM_CREDIT、WAIT_L1_BANK、WAIT_L2_BANK、WAIT_NOC_CREDIT、WAIT_DMA_QUEUE、WAIT_HBM_OUTSTANDING、UCE_PROGRAM_DESC、UNKNOWN、WAIT_MSHR）；每停顿周期恰一 primary owner，显式优先序（事件＞engine 队列满＞stream）；RTL 新原因须映射既有 owner 或经评审扩展；UNKNOWN≠0＝覆盖缺口；互斥归因与重叠计数不得相加（OBS-02/07）；PMU 取自真实组件快照、freeze-then-read、饱和加法＋溢出 sticky（OBS-08）。
- 基线：P0＝W0 固定版本原 Coral；P1/PN＝同一改造硬件、单/多 Context，**同总工作量、精度（BF16 I/O／FP32 内部）、内存配置、频率条件、编译策略**；PS＝单独选定扩大配置，待扩大配置评审后启动（§16.3）。P0 不支持的新语义用等价数值 kernel，须解释范围差异。
- 禁止项：把 validator 周期当 RTL 性能、断言 cycle-equal、PPA／Fmax 宣称、多 VME 利用率估算（§18.1、§22.3、D-29）；"调度机会"与"固定加速比"分别举证（PERF-07）；短时独立前进（功能）与端到端加速（性能）分开展示。

## 5. 数据流、控制流和时序路径

- **验收流**：配置注入（W0/W6）→ 运行联仿（W1）→ 边界日志流式落盘 → run 终态或显式声明捕获终点（含已知故障/死锁窗口的声明结束 cycle、quota 截断）时**封窗**（写入封窗记录：首/末 seq、记录数、声明结束边界及类型、gap/quota 状态；该记录本身纳入窗口并受 C6 校验）→ C1…C5 → C6（若需重放）→ C7 汇总 manifest → 归档（窗口、封窗记录、verdict、blob、报告互引）。
- **重放流**：载入窗口 → C6 门检（不过＝显式"不可完整重放"）→ 按日志请求驱动 RTL、身份匹配回放响应 → C2/C3/C5 合同等价比对 → 重放 verdict 并入 manifest。
- 控制流要点：封窗前记录不可变更（内容寻址）；checker 只读；任何 FAIL 必须携带最小复现引用（window_id＋seed＋注入计划）。

## 6. 配置、PPA、性能模型和 PMU

- 默认全窗口捕获，但受配置化 file quota 约束（§3.3 捕获配额：超限停写并标 gap，不无限扩张）；RTL 诊断插桩只需紧凑 ID；Host 被动捕获实际功能端口 payload，hash 只是 blob 校验，不能代替字节（OBS-10）。
- 计数导出 change-only；初始化阶段不计入工作负载周期（OBS-11/13）。
- blob store 内容寻址、去重（同程序装载合并引用）；重放包只含被引 blob。
- RTL 侧插桩面积／扰动由 W6/W1 评估并单列，不计入正常模式性能（OBS-05）；debug FIFO 容量、保留寄存器、debug ring 容量＝由后续规格冻结（OBS-18）。

## 7. RTL/软件实现建议

### 8.2 NEST 语料映射与 N05→T-20 裁决

- 语料（VER-13）：静态 DAG S01～S12、时间分块 T01～T04（NEST 内部编号，与本规格 T-ID 无关）、专项 N01～N10、非法切分反例、参数化维度，全部带 invariants 与元数据（节点/边/Context 划分/资源配置/期望/禁止依赖），不允许只断言最终输出。
- RTL 至少通过 P0 集合的 Tile 级等价场景；CS1 出口用 T-39/T-40 承接；CS2 出口用 T-59 承接 P0/P1。
- **N05 裁决**：NEST 规范 N05 原期望"两阶段提交/全部回滚，不留部分绑定"（规范 :363）与 r5 T-20 冲突。按 VER-13"规范中 N05 的期望按本文 T-20 更新"，本轮生效期望＝两阶段准入（整合合同(b)）：失败发生在最终 COMMIT 授权**之前**＝仅该 Tile 补偿释放本次 ticket（父 pin/R＋本地 hold，票据保持到释放证据）；最终授权**之后**不 ROLLBACK＝已授权 Task 走 CANCEL/drain 排空；最终 Arena/lease/pin/Route 全归零、无部分绑定残留。该覆盖作为测试 manifest 中的期望覆盖条目实现，NEST 规范文件本身待后续统一修订（本轮不改）。N05 于 CS2（P1 集）执行（T-59）。
- N01→T-15/N10 关联、N03→T-21/T-43、N06→T-08、N07→T-04、N08→T-42、N09→T-43 空池分支：NEST 期望与本规格 T 行一致，无冲突。

### 8.3 W7 自身验收（mutation／负例，不只 happy path）

- **checker 杀伤套件**：对每个 checker 注入至少一个种子缺陷并要求 FAIL——重复终态（C3）、漏唤醒（C2）、提前释放（C2/C3）、旧代写新代（C2）、credit 不平衡（C3）、seq 断档与 hash 不符（C1/C6）、窗口缺口仍宣称可重放（C6）、**删除末尾记录但保留连续前缀的截断窗口仍宣称可完整重放（C6，靠封窗记录计数/边界不符抓住）**、pending 冒充完成／deadline 到点通过（C5/C7）、dangling 证据引用（C7）。杀伤未证明的 checker 不得投入 T 用例判定。
- **重放演示**：完整窗口内已知故障单侧重放成功（CS1 出口（5））；缺口窗口被拒并输出"不可完整重放"。
- **伪进展禁令**：manifest 不存在"超时＝通过"或"剩余 pending 视为完成"；终止检查只在 §3.4 C5 环境假设下判定。

### 8.4 性能验收口径与数值判据

- 实验前冻结：工作负载集（含内存等待可隐藏、VME 饱和、控制密集、随机访存）、基线（P0/P1/PN/PS 定义）、统计边界（PERF-03/06）；不事后挑选。
- 度量：PERF-01（吞吐/makespan/单任务延迟/尾延迟/单 Context 回归）、PERF-02（等待原因/有效发射/退休/引擎活动/访存占用）、PERF-04（gather 有用/实际字节、合并率、outstanding）、PERF-05（计时终点含输出写回与完成语义）、PERF-07（调度机会 vs 固定加速比分列）。允许部分饱和负载不加速，但必须解释。
- 数值判据（T-01/T-29/T-39/T-61/T-68 共用）：独立参考必须建模**已确认的**数值 profile——内部 BF16×BF16→FP32 路径为 ROD（用户已确认保留 Coral 内部 ROD），并按真实证据建模实际有限宽与累加归约顺序，不作 generic FP32 FMA 顺序假设；BF16 最终输出转换舍入**单列待review**（建议 RNE 尚未批准）。C4 相关行仍受 gate：封印构建完成、独立 oracle 就绪、实跑对拍完成前不得记 PASS。冻结后默认判据＝结果比特一致（含 flags/越界行为），**不自降通过标准**：参考无法复现须评审冻结参考语义或记 BLOCKED/FAIL，不得降 ULP 或修改参考以迎合 DUT；ULP 类判据仅在评审显式批准后作为独立补充，不替代 bitwise 合同；不得默换 FP16 或以 RVV/scalar 冒充 VME。
- 精度范围澄清：BF16 收窄只针对张量 I/O 与内部 FP32 累加路径；i32 标量地址／索引／控制整数是既有 ISA 能力，不构成新增数值精度，也不在 C4 的 BF16 化范围内（共享合同）。
- 禁止出现在报告：Fmax/面积/功耗宣称、多 VME 利用率估算、validator 周期当 RTL 真值、debug 扰动混入正常性能。

## 9. 风险、取舍和后续细化方向

1. 数值 profile：内部 BF16×BF16→FP32 已确认保留 Coral ROD（用户裁决），实际有限宽与累加归约顺序须以真实指令/微架构证据建模；BF16 最终输出转换舍入仍单列待review（建议 RNE 尚未批准）。C4 相关行在构建、独立 oracle 与实跑完成前不得记 PASS（gate 不因 profile 确认而解除）；冻结后 bitwise 合同下不匹配只能是 FAIL，**不得把 oracle 降为 ULP 或修改参考来迎合 DUT**；ULP 类判据只能在评审显式批准后作为独立补充项。
2. payload blob 规模、hash 算法、记录二进制编码：由后续规格冻结，先以逻辑 schema 评审。
3. RTL 插桩端口（OBS-10/12）与 W6 debug FIFO 的容量/扰动边界需 W1/W6 联合评审，避免 checker 依赖改变被测行为（OBS-05）。
4. `StallReason` 扩展枚举（RVV 队列满、VME 忙[N>1 按实例]、LSU slot 满）须评审映射表后固定，避免 UNKNOWN 漂移。
5. 条件 N2 子项（T-68 的 N≥2 部分、T-28 多实例公平性）依赖 W3 N≥2 实例模型冻结与实现宣称；此前 status＝DEFERRED_NOT_APPLICABLE（非 BLOCKED），一旦宣称 N≥2 实现即转 mandatory，不得默认通过。
6. PS 基线与 P0 等价 kernel 的范围差异解释义务（PERF 报告必含）。
7. 重放仅单侧承诺；双侧重放、跨窗口拼接不在本轮范围。
8. NEST 规范文件 N05 行的正式文本修订挂在后续文档轮（本稿规定未来测试 manifest 覆盖，尚未创建），需 总体设计 在决策登记表跟踪以免 dangling。
