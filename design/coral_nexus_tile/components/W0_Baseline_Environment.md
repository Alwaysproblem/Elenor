## 1. 定位、目标和 First Silicon cutline

W0 是 CS1 联仿的**可复现运行载体**：一个锁定容器环境 + 两份上游源码锁 + `hardware/coral_nexus` 独立子项目骨架 + P0/P1 基线入口与参数 manifest 合同。它不实现任何 RTL、协议或验证逻辑。

| 目标               | 内容                                                                                        | 需求依据（r5）       |
| ------------------ | ------------------------------------------------------------------------------------------- | -------------------- |
| G0 环境就绪        | 锁定版本、支持配置、上游/项目小 kernel 回归、结果可重放                                     | §20.2 G0、§22.1      |
| P0 基线            | 固定版本原 Coral、受支持原构建可稳定生成并运行                                              | §16.3 P0             |
| P1 基线入口        | 改造后 Tile 同资源单 Context 活跃的运行与记录入口（RTL 属后续阶段）                         | §16.3 P1、PERF-01    |
| 参数/产物 manifest | 硬件/编译器 SHA、生成目标、参数、SV 宏、ISA/ABI、工具链版本、已知限制；每字段标注是否被消费 | PAR-01、PAR-08、§3.3 |
| 单一锁定环境       | 容器与 devcontainer 共用同一 Dockerfile 与镜像 digest；宿主零安装、零 sudo、零全局 pip      | prompt.md「注意」    |
| 证据边界           | 性能只以 RTL cycle 证据报告；无 PPA/FPGA 宣称                                               | §16.4、§22.3、VER-17 |

非目标：不引入 Gemmini/sbt 流程（Coral 实为 Bazel，见 §3）；不含 FPGA/CS2/CS3；不修改 `pipeline_validator` 代码；不写文件级实施计划；不冻结物理参数（未知值一律「由后续规格冻结」）。

### 3.3 环境状态机

| 状态             | 进入条件                                                                           | 失败出口                                  |
| ---------------- | ---------------------------------------------------------------------------------- | ----------------------------------------- |
| S0 LOCKED        | 源码锁 manifest 写入（两个 SHA + 子模块 pin + 补丁序列号）并入库                   | 锁文件缺失/SHA 不符 → 阻断                |
| S1 IMAGE_BUILT   | 由锁定 Dockerfile 构建镜像，digest 写入 manifest；`--build-arg _UID/_GID` 取自宿主 | 构建失败或 digest 无法记录 → 阻断         |
| S2 OFFLINE_READY | Bazel 仓库缓存/vendor 数据集 + conda/pip 离线包就位并做一次断网重放                | 断网重放需联网 → 记缺口，不冒充离线可复现 |
| S3 P0_VERIFIED   | 上游受支持目标在容器内构建并通过其 cocotb/示例回归，产物与 trace 可重放            | 目标失败 → 上游偏斜问题，上报不静默改补丁 |
| S4 P1_READY      | 改造 Tile 的生成目标名、manifest 差异字段、基线配置就绪（RTL 语义由后续阶段填）    | 无                                        |

再生成触发器：任一上游 SHA 或补丁序列变化、Dockerfile 变化、Bazel/工具链版本变化、manifest 指纹字段变化（PAR-06 口径）→ 回 S0 重走，并在 manifest 中记录旧 digest 作废原因。

### 6.2 合法性检查（环境检查命令承担）

Chisel/SV/software 参数跨域一致（PAR-02）；R ≤ context_count、context_count 取值域（PAR-09）；模式混比拒绝（PAR-05）；「已声明未接线」字段不得计入支持集合（PAR-08，对应 X-13 的 `uce_dispatch_per_cycle` 类教训）；指纹变化必须作废旧 artifact（PAR-06）；两把上游 pin 各自构建产物的 kernel 机器码兼容性必须实测通过才可标 supported（§9.1 R2）；ISA/ABI 字段必须由实际编译命令/ELF 提取并与 `cc_toolchain_config.bzl` 的 march/mabi flag 交叉核对，README 口径仅作参考、不一致时以构建规则为准（§9.1 R11）。

### 6.3 P0/P1 基线与性能边界

- P0＝上游受支持原构建（§5.1 命令族）；P1＝改造后 Tile、同一硬件资源仅一个 Context 活跃；两者与 PN 使用相同总工作量、精度、内存配置、频率条件与编译策略（§16.3）。P0 不支持的新控制语义用等价数值 kernel 比较并解释范围差异。
- P1 就绪的最低环境判据：目标名与差异字段进 manifest；基线配置与 P0 同口径的可比字段（workload、seed、fidelity、max_cycles、context_count）登记；RTL 语义验收归 T 用例与 W2～W4。
- 性能/PPA 边界：性能宣称只以 RTL cycle 证据 + validator PMU 报告（PERF-01～PERF-04）；无工艺/库/实测证据时不得写 PPA 达标（§22.3）；不做多 VME 利用率估算（D-29）；频率、面积、功耗目标值由后续规格冻结。

## 8. 验证、bring-up 和验收标准

| 检查                | 通过判据                                                                                                                                                                              | 类型 |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| 源码锁一致性        | 检出 SHA/补丁序列与锁 manifest 完全一致                                                                                                                                               | 正   |
| 封存镜像离线复跑    | 以锁中 digest 封存的镜像 + 离线种子断网复跑 §5.1 P0 命令族成功且产物一致                                                                                                              | 正   |
| 源码重建等价        | 按锁（基础镜像 digest + 包版本 snapshot/封存缓存 + 工具链归档 SHA）重建环境并通过同一套 P0 回归；不要求重建 digest 位级相同（OCI 元数据/时间戳可致差异），digest 不作为唯一编译位证明 | 正   |
| P0 回归             | 上游 cocotb/示例/verilator_sim 目标在容器内通过且重放一致（G0 出口）                                                                                                                  | 正   |
| UID/GID             | 容器内非 root；产物属主为调用者 UID                                                                                                                                                   | 正   |
| 锁偏斜负例          | 切换到非锁定提交，或修改受锁定的源文件/补丁 → 检查命令失败并列出差异文件                                                                                                              | 负   |
| 离线缺缓存负例      | 清空缓存断网构建 → 快速失败并列缺失输入清单，不得部分构建后假成功                                                                                                                     | 负   |
| 未接线参数负例      | manifest 中标记「未接线」的字段被写成 supported → 检查失败（PAR-08）                                                                                                                  | 负   |
| 模式混比负例        | 跨 `enableVerification`/retirement 模式的两次结果进同一基线对比 → 拒绝（§3.3、PAR-05）                                                                                                | 负   |
| manifest 缺字段负例 | 缺生成目标名或 SV 宏记录 → 指纹桥接检查失败（PAR-01/02）                                                                                                                              | 负   |

低级模型指南：先读本文件 §3/§5 与所引上游原文 → 实现不变量（单一环境、宿主零变更、每产物带 manifest、只用现存命令或标注未来命令）→ 证明（§8 表逐项）；停止条件：上游 CI 已证目标失败（疑上游偏斜，上报而非改补丁）、离线缺口无法本地补齐（记录缺口并停）、需冻结的物理参数出现（标注「由后续规格冻结」并停该分支）。

### 9.2 已选策略与后续变更边界

- 包版本固定机制：不可变 apt snapshot＋版本／SHA 清单；封存镜像、Bazel／Python／工具链离线种子，分别验证构建和执行复现（W0-02／W0-05）。
- 上游获取采用 A（submodule＋可审补丁），不采用私有 fork 或全量 vendor 作为开发来源；以后迁移只由明确评审触发，不设自动阈值。
- 工具链采用上游锁定的预构建归档；Rocky 源码重建为独立审计备选，不自动降级或作为 CS1 前置。
- devcontainer 放 `.devcontainer/coral_nexus/devcontainer.json` 并引用同一镜像，不维护第二套依赖定义。
